## 1. 왜 이 제품인가 (맥락)

- 사용자는 스와이프형 데이팅 앱 피로 + 매칭 상품화 회의 + 진지한 배우자 탐색(유료 OK)을 동시에 갖고 있음.

- W클럽·퍼스트클래스형 **티켓·1:1**은 참고하되, “상위 1% 클럽·능력남×외모녀 전면”은 **브랜드 얼굴로 쓰지 않기로** 함.

- “판교/테헤란로 소개팅”과 “진지 1:1 프라이빗”을 **한 제품으로 결합**하기로 함.

- 그룹(2:2·3:3) 오피스타운은 **별앱/Later** — 본 MVP에 넣지 않음.

- 생활권만 필터로 얹는 안(A)과 로컬 피벗(C) 중, **C의 무대 + 1:1 프라이빗 루프**로 확정.

## 3. 코어 루프 (구현 불변식)

```text

(공통) 존·직장 인증 + AI 인터뷰 프로필 확정

    → (여) 같은/인접 존 남성 호·불 평가 (무료, 크레딧+)

    → (남) 소개 티켓 → like 준 여성 풀에서 1명 오픈

    → (남) 만남 티켓?

         ├─ No  → 쌍 영구 제외

         └─ Yes → 일정·장소 조율 채팅

              → (만남 전날 또는 T-2h) 사적 채팅 오픈

              → 만남 (장소·음식 제한 없음 — 추천만 제공, D5 폐기)

              → 피드백 → 매너온도

```

불변식:

1. 남성 소개 대상 ⊆ 해당 남성 like 여성

2. 동시 오픈 소개 ≤ 1

3. pass/미사용 만남 티켓 쌍 재큐잉 금지

4. private chat 시각 전 = 조율 채널만

5. 불특정 다수 피드 없음

# 오피스타운 1:1 프라이빗 매칭 — PRD

> 상태: 초안 확정 (인터뷰 기반) · 작성: 2026-07-30

> 레포: `~/dev-private/golden-fishery`

> 한 줄: **같은 퇴근존 직장인이, 이미 호감이 있는 상대와, 카페 한 잔 거리에서 1:1로만 만난다.**

> 기준 문서: 본 PRD · [`HANDOFF.md`](../HANDOFF.md)

---

## 문제

기존 데이팅 앱은 무제한 스와이프·프로필 상품화로 만남을 가볍게 만들고,

하이엔드 검증 앱은 “능력남×외모녀·클럽 입장” 프레임으로 진입 장벽과 계급감을 키운다.

결혼정보회사는 무겁고 비싸다.

타깃 사용자는:

- 데이팅 앱 피로 / 매칭 상품화에 회의감

- 진지한 만남·배우자 탐색 의 (비용 지불 용의)

- 결혼정보회사보다는 가볍되, **한 번의 만남에 진정성**을 두고 싶음

- 스펙 전면 비교보다 **결이 맞는 사람**을 원하지만, 현실적으로 시간·거리·신뢰는 필요

**풀고 싶은 것:**

가까운 생활권(오피스타운)에서 신뢰를 확보한 직장인끼리,

스와이프 없이 **한 번에 한 사람**만 소개받고,

비싸고 긴 데이트가 아닌 **카페 1차**로 서로를 확인할 수 있게 한다.

## 대상 사용자와 시나리오

### 일차 타깃

| 역할 | 페르소나 | 동기 |

|------|----------|------|

| 여성 | 판교·테헤란로 등 허브 직장인, 20대 후반~30대 | 가벼운 톡방·스펙 쇼핑 없이, 퇴근 후 부담 없는 1차로 진지한 상대 확인 |

| 남성 | 동일 허브 직장인, 비용 지불 용의 | 이미 호감을 준 여성만 순차로 보고, 시간·돈을 아끼며 만남까지 연결 |

### 핵심 시나리오 (해피패스)

1. 가입·퇴근존(오피스타운)·직장 인증 + AI 인터뷰로 프로필·이상형 생성

2. 여성이 같은/인접 존 남성 프로필을 **무료**로 호·불 평가 (크레딧 적립)

3. 남성이 **소개 티켓**으로, 자신에게 호감을 준 여성 풀에서 **1명씩** 프로필 오픈

4. 남성이 **만남 티켓** 사용 여부 결정 (미사용 = 해당 상대와 추가 액션·재매칭 불가)

5. 만남 티켓 사용 시 **일정·장소 조율 채팅**만 오픈 (장소 종류 제한 없음)

6. 만남 전날 또는 당일 2시간 전에 **사적 채팅** 오픈

7. 만남: **장소·음식·예산을 제품이 제한하지 않는다.** 추천 목록만 제시 (D5 폐기)

8. 만남 후 피드백 → 여성 **매너온도** 반영

## 요구사항

### 기능

#### F1. 가입 · 퇴근존 · 직장 인증

- 사용자는 서비스 허브 **퇴근존** 중 하나(이상)를 선택·인증한다.

  초기 후보: 판교·정자권, 테헤란로·역삼권 (확정 목록은 미결).

- **직장인 인증** 필수 (방법: 회사 이메일 / 명함·재직 서류 / 기타 — 미결, 하나만 먼저).

- 동일 존 또는 **인접 존** 우선 매칭.

- 인증 실패·허위 시 가입 거부 또는 이용 정지.

#### F2. 인터뷰 프로필 <span>(D9: "AI" 표기 제거 — 구현은 규칙 기반)</span>

- 온보딩에서 **인터뷰**로 **자기 소개·가치관·이상형**을 포함한 프로필 초안 생성. 사용자 대면 문구에 "AI"를 쓰지 않는다.

- 사용자는 초안을 수정·확정 후 노출.

- 프로필 품질이 소개 티켓 가치의 핵심이라는 전제 (짧은 스펙 나열만으로 완료 불가).

#### F3. 여성: 무료 호·불 평가 + 크레딧

- 여성은 과금 없이 남성 프로필을 보고 **호감 / 비호감**(또는 동등한 이진·소수 척도) 평가.

- 평가를 많이 할수록 **크레딧** 적립 → 별도 혜택 (혜택 목록 미결: 소개 우선·뱃지·이벤트 등).

- 평가 UX는 빠르게 (관심사·간단한 메트릭·선택적 사주 등은 **옵션 신호**, 핵심은 호·불).

#### F4. 남성: 소개 티켓 → 순차 1명 오픈

- 남성은 소개 티켓을 사용해, **자신에게 호감을 준 여성 풀**에서만 추천을 받는다.

- **한 번에 한 명**만 프로필 오픈 (동시 복수 오픈 없음).

- 큐레이션 톤: 앱이 “커플매니저/컨시어지”처럼 **한 명씩 전달** (실제 사람 개입 여부는 미결).

#### F5. 만남 티켓 · 영구 제외

- 소개를 받은 뒤 남성은 **만남 티켓 사용 / 사용 안 함**을 선택해야 한다.

- 사용 안 함: 해당 프로필에 추가 액션 불가, **동일 상대 재매칭 큐 제외**.

- 사용: 일정·장소 조율 채팅 시작.

#### F6. 채팅 게이트

- 만남 티켓 직후: **일정·장소 조율에 필요한 채팅만** (사적 잡담 최소화 UI/카피).

- **사적 채팅**은 만남 **전날 18시**에 오픈 **(확정 — D4)**. 확정 시점이 이미 전날 18시를 지났으면 즉시 오픈.

- 목적: 약속 확인 + 가벼운 톡방 데이팅 방지.

#### F7. 1차 만남 프로토콜 — **폐기됨 (D5). 아래는 옛 서술이다.**

> **현행 정책: 제품은 장소·음식·예산을 제한하지 않는다.** 추천 목록만 제시하고 선택은 당사자가 한다.
> `place_kind`를 관측용으로 기록해 분포를 보되, 강제하지 않는다.
> 자세한 내용은 [`docs/prd-after-mvp.md`](./docs/prd-after-mvp.md) §F6 참조.

#### F8. 사진 진위 · 매너온도

- 여성(및 필요 시 양측) 프로필 사진: **프사기 방지** 정책 (라이브니스/최근 사진 검증 등 — 수단 미결).

- 만남 후 피드백으로 여성 **매너온도** 갱신.

- 매너온도는 재소개 우선순위·제재·노출에 영향 (상세 공식 미결).

#### F9. 프라이빗 노출

- 불특정 다수에게 얼굴·프로필이 피드로 나열되지 않음.

- 소개·호감 평가 맥락에서만 상대에게 노출되는 **1:1 프라이빗** 모델.

## 데이터 · API 계약 (초안)

구현 전 스키마는 변동 가능. 개념 엔티티만 고정.

| 엔티티 | 주요 필드 |

|--------|-----------|

| `User` | role(gender), hub_zone_ids, work_verified_at, manner_temp(여), credits(여) |

| `Profile` | ai_interview summary, values, ideal_type, photos[], cafe_or_drink_pref |

| `Affinity` | from_female_id, to_male_id, signal(like/pass), created_at |

| `IntroQueue` | male_id, female_id, status(queued/opened/passed/meeting/expired) |

| `TicketLedger` | user_id, type(intro/meeting), qty, source(purchase/grant) |

| `Meeting` | intro_id, place_type(cafe/drink), scheduled_at, private_chat_opens_at, status |

| `Feedback` | meeting_id, from_user, scores, manner_delta |

핵심 불변식:

1. 남성에게 오픈되는 소개 대상 ⊆ 해당 남성에게 like한 여성.

2. 남성 동시 `opened` 소개 ≤ 1.

3. `passed`(만남 티켓 미사용) 쌍은 재큐잉 금지.

4. `private_chat` 오픈 시각 이전에는 조율 채널만.

| 동시 기기·중복 결제 티켓 | 멱등 처리 |

| 이혼·기혼 등 | 가입 자격 정책 명시 필요(미결) |
