# 통신사 본인·성인 확인 전환 (KCP + 포트원 V2)

2026-10-26 대표 확인: **본인인증은 PortOne/KCP 심사 중, 결제는 토스페이먼츠 유지**. 이 변경으로 운영 인증/결제 플래그는 켜지 않는다. 자체 문자 OTP는 성별·성인 여부를 제공하지 않는다.

## 환경변수로 개발 인증 생략 / 실제 인증 선택

| 모드               | 프런트엔드 환경변수                                                 | Edge 환경변수                            | DB `app_settings.identity_required` |
| ------------------ | ------------------------------------------------------------------- | ---------------------------------------- | ----------------------------------- |
| 로컬 인증 생략     | `VITE_DEV_AUTH_BYPASS=true`, `VITE_CARRIER_IDENTITY_ENABLED=false`  | `DEV_AUTH_BYPASS=true`                   | `false` (로컬 DB만)                 |
| 현재 문자 OTP 베타 | `VITE_DEV_AUTH_BYPASS=false`, `VITE_CARRIER_IDENTITY_ENABLED=false` | `DEV_AUTH_BYPASS=false`                  | `false`                             |
| KCP 필수 인증      | `VITE_DEV_AUTH_BYPASS=false`, `VITE_CARRIER_IDENTITY_ENABLED=true`  | `DEV_AUTH_BYPASS=false` + PortOne 키 3개 | `true`                              |

- **기본값은 인증 생략 OFF**다. 생략은 개발 빌드와 정확한 loopback Supabase URL에서만 허용한다. Edge도 실제 서버의 `SUPABASE_URL`을 파싱해 로컬 호스트(`kong`, `127.0.0.1`, `localhost`, `::1`)와 명시적 플래그를 확인한다. 요청의 Origin/Host나 비슷한 도메인 문자열로 허용하지 않는다.
- 개발 모드도 약관 동의·성별·회사 이메일·비밀번호·지역·테스트 전화번호는 입력한다. 회사 이메일 코드를 발송하지 않고 로컬 Auth 계정을 만들며, 휴대폰은 **인증 없이 계속**으로 코드 입력을 생략한다. 번호 중복 검사와 서버의 정상 코드 소비는 유지한다. `identity_verified_at`/DI를 위조하지 않으며, 자기 입력 생년월일의 성인 검사도 유지한다.
- 브라우저 플래그만 켜서는 개발 계정을 만들 수 없다. `signup-identity`의 로컬 상태 검사와 Edge 플래그가 함께 필요하다. 휴대폰도 서버 플래그가 OFF면 거절한다. 개발 모드는 SMS 키가 있어도 문자를 보내지 않는다.
- KCP 플래그는 본인확인 경로를 선택한다. 개발용 회사메일 우회와 별개이므로 두 플래그를 동시에 켜면 KCP는 생략되지 않는다. 인증 없이 전체 가입을 확인할 때는 표의 첫 행을 쓴다.
- `.env.development.local`에 프런트엔드 플래그, `supabase/functions/.env`에 Edge 플래그를 둔다. 두 파일은 Git에서 제외된다. 바꾸면 해당 Vite/Edge 개발 프로세스를 다시 시작한다. 실인증 검증 때는 프런트엔드와 Edge 모두 `false`로 바꾼다. 로컬 Auth의 이메일 자동확인 설정은 운영에 복사하지 않는다.
- DB 게이트는 환경변수로 덮어쓰지 않는다. 브라우저를 조작해도 DB가 가입을 거절해야 하므로, KCP 필수 모드 전환 시 아래 절차로 DB 게이트까지 켠다. **키 저장만으로 운영이 자동 활성화되는 구조가 아니다.**

### 심사 후 키 설정

Supabase Edge Functions → Secrets에만 저장:

```dotenv
PORTONE_STORE_ID=발급된_store_id
PORTONE_KCP_IDENTITY_CHANNEL_KEY=발급된_LIVE_본인확인_channel_key
PORTONE_API_SECRET=발급된_V2_API_secret
DEV_AUTH_BYPASS=false
```

API secret은 `VITE_` 변수로 만들지 않는다. 코드 추가 없이 키·채널 설정 및 아래 전환 절차로 웹 가입을 실검증할 수 있다. 키가 빠지거나 채널이 TEST/다른 채널이거나 검증 응답이 불완전하면 가입 인증은 실패 처리한다. 통신사 계약·실기기 인증을 통과했다고 표시하지 않는다.

새 가입 구조는 `약관·개인정보 동의 → 통신사 본인·성인 확인 → 회사 이메일 → 직장 지역 → 프로필 작성`이다. 통신사 결과에서 성별·생년월일을 가져오므로 성별 선택 화면은 없고, 생년월일은 다시 입력하거나 고치지 않는다. 미개통 베타에서는 약관을 가장 먼저 받되 수기 성별·가입 후 문자 OTP를 유지한다.

## 계약 심사 중 베타 운영

- 대표 결정에 따라 키 발급·실인증 검증 전에는 `약관 동의 → 성별 → 회사 이메일 → 직장 지역 → 문자 OTP → 생년월일 등 기본 정보 → 생활 정보 → 인터뷰`로 가입을 받는다. 기존 문자 발송 설정을 그대로 사용하며 운영 인증번호를 우회하지 않는다.
- 생년월일은 직접 입력하고 한국 날짜 기준 만 19세 이상인지 앱과 DB 양쪽에서 검사한다. 필수 생년월일이 없거나 나이 조건에 맞지 않으면 기본 정보 다음 단계로 갈 수 없다.
- 문자 OTP는 번호 수신 가능 여부만 확인한다. 입력한 생년월일·성별·실명을 증명하지 않으며 `identity_verified_at`을 채우거나 통신사 본인·성인 확인 완료로 표시하지 않는다. 베타 가입 허용은 PG 심사 충족이나 유료 출시 승인으로 간주하지 않는다.
- `CARRIER_IDENTITY_ENABLED`와 `app_settings.identity_required`는 계속 꺼둔다. 키가 발급되어도 자동 전환하지 않고 아래 실검증과 전환 절차를 따른다.

## 가입 전 인증과 동의 기록

- 동의 시 서버가 짧은 가입 세션을 만든다. 브라우저에는 임의의 256비트 비밀 토큰, DB에는 토큰 해시만 둔다. `begin_signup`, `signup_session_status`만 비로그인 호출이 가능하며 회원·티켓 API나 임시 테이블은 공개하지 않는다.
- `signup-identity`가 서버에서 만든 인증 ID와 해당 가입 세션을 연결하고, 공급자의 LIVE 결과를 직접 조회한다. 성별·생년월일·번호·DI가 빠지거나 만 19세 미만이면 진행하지 않는다. 브라우저는 검증된 신원을 직접 저장할 수 없다.
- 회사 메일 인증 뒤 `create_signup_profile` 한 트랜잭션에서 신원·번호·원래 동의 시각·약관 버전과 회원을 연결한다. 인증된 성별이 수기 값보다 우선하며 신원 중복·다른 계정의 토큰 재사용은 거절한다.
- 가입 세션은 1시간 유효하고 15분 주기로 만료 데이터를 삭제한다. 가입 완료 시 임시 생년월일·성별·번호·DI 해시는 즉시 비운다. 가입 미완료 정보는 처리방침의 최대 24시간보다 짧게 보관한다.
- 일반 재방문은 이전 가입을 이어갈지 먼저 선택한다. 모바일 인증창에서 돌아오는 경우에는 같은 브라우저가 시작한 인증 ID만 받아 이어간다.

## 대표가 먼저 해야 할 일

1. 포트원 V2 계정에서 **KCP 휴대폰 본인확인** 서비스 계약·채널을 신청한다. 포트원은 결제창을 대체하는 것이 아니라 통신사 본인확인 연결에만 쓴다. KCP에서 인증 결과 URL `checkout-service.prod.iamport.co`와 **신규 연동방식(V2)** 사용을 설정한다. [KCP 연동 안내](https://developers.portone.io/opi/ko/integration/pg/v2/kcp-v2-identity-verification?v=v2)
2. 발급받은 `PORTONE_STORE_ID`, `PORTONE_KCP_IDENTITY_CHANNEL_KEY`, `PORTONE_API_SECRET`을 **Supabase Edge Functions secrets**에 저장한다. 저장소/메신저에 원문을 올리지 않는다. 채널은 **LIVE 타입의 KCP 휴대폰 본인확인 전용**으로 사용하고, 계약 결과에서 `gender`, `birthDate`, `phoneNumber`, `di`가 실제로 제공되는지 확인한다. TEST 채널 결과는 운영 서버에서 거절한다. [포트원 결과 필드](https://developers.portone.io/opi/ko/extra/identity-verification/readme-v2)
3. 개인정보 처리방침에 본인확인 대행사, 처리 항목(검증 생년월일·번호·DI의 해시), 보유/파기 및 위탁 사항을 검토·반영한다. 실제 법률 문구와 동의 범위는 대표/전문가가 확인한다.

## 기술 롤아웃 순서

1. `20261016130000_s58_carrier_identity.sql`, `20261017180000_identity_first_signup.sql`, `20261026120000_carrier_identity_completion.sql`을 적용하고 `carrier-identity`(기존 회원)·`signup-identity`(가입 전)·`phone-otp` Edge Function을 배포한다. 시크릿 미설정이면 인증 요청은 503으로 실패한다. 배포만으로 운영 통신사 인증을 켜지 않는다.
2. 스테이징/실계약 테스트 계정으로 **실제 KCP 인증창**을 열어 성인, 미성년, 취소, 중복 DI/번호, 리다이렉트, 기존 회원 재인증을 확인한다. 서버는 브라우저의 성공 신호만 믿지 않고 PortOne API에서 `VERIFIED`와 검증된 고객 정보를 조회한다. 인증 ID는 서버가 사용자에게 발급하고 15분 동안 한 번만 쓴다.
3. GitHub 저장소 Actions variable `CARRIER_IDENTITY_ENABLED=true`를 설정한 뒤 배포한다. Release gate가 웹 빌드에 `VITE_CARRIER_IDENTITY_ENABLED=true`를 전달한다. 새 가입은 동의 직후 본인·성인 확인을 받고 회사 메일로 넘어가며 성별 선택을 생략한다. 기존 회원은 `/verify-phone`에서 재확인한다. **현재 네이티브 앱 웹뷰에는 아직 이 경로를 열지 않는다.** 앱 심사/배포 전에 외부 브라우저↔앱 복귀 흐름을 별도 구현·검증해야 한다.
4. 기존 회원이 인증할 수 있음을 확인한 뒤에만 `app_settings.identity_required=true`를 운영 DB에서 켠다. 이때 미인증자의 새 소개·평가·티켓 주문·만남·메시지는 DB 트리거에서 막힌다. 활성 주문이나 이미 열린 약속의 전환 정책은 운영자가 사전에 정해야 한다. 장애 시 이 값을 `false`로 되돌릴 수 있지만, 그러면 성인 확인 게이트가 풀리므로 심사·유료 출시 상태를 함께 중단한다.
5. 인증창, 완료 화면, 미성년 거절, 고객상담, 결제·사용 내역을 실제 화면으로 캡처해 토스 결제경로 PPT를 다시 만든다. 공급자 계약과 실인증 없이 합성 화면을 제출하지 않는다.

## 보안·품질 기준

- 신규·기존 회원은 동일한 서버 검증기로 LIVE 채널, 인증 ID, 성별·생년월일·번호·DI를 검증한다. 기존 회원의 수기 성별과 공급자 결과가 다르면 인증을 거절하고 고객센터로 안내한다. 기존 소개/매칭 이력을 자동으로 바꾸지 않는다.
- 완료 응답이 유실되면 같은 소유자·인증 ID의 서버 저장 결과를 반환한다. 이미 소비된 인증으로 새 신원을 덮어쓰지 않는다. 가입 세션 자체가 만료/청구된 경우나 계정 탈퇴 후에는 완료 결과를 재사용하지 않는다. 재시도는 이전 ID를 먼저 확인하므로 새 유료 인증을 무작정 시작하지 않는다.
- 공급자 조회에는 12초 제한이 있다. 통신 오류는 미확인 상태로 유지하며 인증 성공을 추정하지 않는다. 원본 공급자 응답/DI/전화번호는 로그나 사용자 오류 문구에 노출하지 않는다.

- `finish_carrier_identity`는 service role 전용이며 본인과 결부된 인증 시도만 완료한다. 원본 DI는 저장하지 않고 SHA-256 해시를 비공개 테이블에 보관해 중복가입을 막는다. 탈퇴 시 해시·인증 메타데이터·번호를 파기한다.
- KCP에서 필수 필드가 빠졌거나 PortOne 조회가 실패하면 인증되지 않는다. 조회된 인증 ID, 설정한 채널 키, LIVE 타입이 모두 일치해야 한다. 화면이 직접 생년월일/인증 시각을 설정할 수 없다.
- `identity_required=false` 상태는 **출시 준비 상태가 아니다.** 기존 문자 OTP와 자가 입력 생년월일이 계속 유효하다. 토스 심사 제출 또는 유료 출시 전에 운영 플래그와 실제 인증 기록을 확인한다.
- 로컬 브라우저 테스트의 공급자 응답은 검증용 fixture다. 약관 선행, 취소·모바일 복귀, 성별 선택 생략, 실제 DB의 신원·동의 이전은 검사하지만 실제 KCP 인증창을 통과했다는 증빙은 아니다.
