# Concierge 두 트랙 실행 경계

2026-10-26. [모델·데이터 전략](concierge-model-data-strategy.md)과 [V2 신뢰 로드맵](concierge-v2-reliability-roadmap.md)의 구현 시작 범위를 정리한다. 이 문서는 운영 활성화·모델 품질 검증·학습 승인·신규 과금 정책을 뜻하지 않는다.

## 트랙 A — 현재 API와 개인 세션의 신뢰

현재 LLM API를 유지하고, 기억은 모델 가중치가 아닌 소유자가 정정·삭제할 수 있는 private 저장소에 둔다. 먼저 현재 세션과 업무 대상이 연결되는지, 최근 상태와 공개 근거를 정확히 읽는지, 본인이 말한 사실과 AI 제안이 섞이지 않는지 확인한다. 모델 교체가 이 작업의 선행 조건은 아니다.

이번 첫 이정표는 V2 로드맵의 **A 신뢰 결함 마감** 범위다. 한국어 의도/부정 처리, 홈과 대화의 최신 context 공유, 실제 대상이 없는 행동 숨김, 고정 안내의 모델 0회 처리, 실패·진행 상태의 정직한 문구를 회귀로 확인한다. 구현별 완료 여부는 코드와 해당 검증 결과로 판단하며 이 문서만으로 완료 처리하지 않는다.

현재 R02의 범위는 최신 context 공유까지다. 과거 메시지의 버튼은 특정 새 상대에게 다시 연결하지 않고 목록에서 대상을 선택하게 한다. 메시지별 변경 불가능한 대상·업무 ID를 영속화하여 과거 대화의 정확한 대상까지 복구하는 기능은 다음 업무 지속성 단계에 남는다.

### 첫 구현 결과

| 항목           | 구현 경계                                                                                                                                                                                                                          |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 개인 세션      | 기존 `assistant_turns`를 재사용하고 `assistant_preferences.session_id`로 계정당 활성 대화 한 개를 연결한다. 홈/전체/재로그인 모두 같은 저장소를 읽으며, 클라이언트가 다른 세션 소유자를 고를 수 없다. 다중 대화방은 만들지 않는다. |
| 개인정보 정정  | 새 기억 추가는 세션을 유지한다. 기록 삭제·기억 수정/삭제/만료는 세션을 회전시키고, 동의 철회·비활성화는 세션을 비운다. 기존 revision 검사를 함께 사용해 늦은 응답이 삭제 내용을 복구하지 못한다.                                   |
| 보관·모델 문맥 | 원문은 기존 최대 30일, 승인 기억은 90일/최대 10개, LLM에는 최근 완료 상담 6개와 승인 기억만 전달한다. 세션 식별자를 추가했다고 무기한 기억하거나 전체 대화를 모델에 보내는 것은 아니다.                                            |
| 사실의 출처    | 모델 입력을 사용자 발언/과거 AI 제안/사용자 승인 기억으로 분리한다. AI가 추천했던 내용을 사용자의 확인된 취향으로 재사용하지 않도록 생성·검증 프롬프트를 함께 수정한다.                                                            |
| 비용 없는 안내 | 빠른 도움은 AI 동의 전에도 사용할 수 있고 LLM·상담 기록 저장 없이 안내한다. 동의한 사용자가 보낸 서비스 질문은 기존 서버 고정 응답을 사용한다. 일반 고민만 현재 LLM 경로를 사용한다.                                               |
| 정확한 동선    | 사진·기본정보·소개글 수정과 복합 요청을 나누고, 수정 요청 원문을 편집 화면으로 전달한다. 아직 답변이 없는 만남 요청을 ‘답을 받았다’고 표시하지 않는다.                                                                             |

출시 코드는 기존 모델 환경변수와 서버 승인 흐름을 유지한다. 새 구독·크레딧·추가 정보 수집·자동 호감/결제/일정 실행은 도입하지 않는다. 운영 비서 활성화는 이번 구현 범위에 포함하지 않는다.

다음 출시 단계에는 별도 검증이 남는다.

| 단계           | 다음에 확인할 계약                                                               |
| -------------- | -------------------------------------------------------------------------------- |
| 접근·운영 안전 | 상대 접근 재검사, 동의/고지 버전, release 상태, 경합·장애 회귀                   |
| 예산·계측      | 생성/검증별 사용량, 원자적 예약·동시성, timeout 비용 보류와 정산, 공통 중단 경로 |
| 업무 지속성    | 대상/초안/원본 버전과 승인한 변경점, 재시작·만료·응답 유실 시 같은 영수증 복구   |
| 개인화 확대    | 승인 기억의 사실·희망·기간, 정정·삭제 전파, 목적별 동의와 사람 품질 평가         |

이는 V2 로드맵 B/C/D에 해당하며 현재 세션 수정만으로 전부 해결되지 않는다. 기존 정책·보유 기간·티켓 계약을 임의로 바꾸거나 새로운 구독 가격을 정하지 않는다. 전역 비용 상한·새 처리 목적·운영 활성화는 각각 필요한 결정과 검증을 거친다.

## 트랙 B — 분리된 오픈 모델 연구

모델·학습 도구 비교, 데이터 작성 예시, 평가·배포 경계, 6주 공부 순서는 [After Writer 자체 모델 학습 설계서](after-writer-training-blueprint.md)를 따른다. 이 설계서는 연구 실행·비용 집행·운영 교체 승인이 아니다.

현재 구현물은 [오프라인 평가 도구](../research/concierge-model/README.md)다. 운영 import·DB 연결·provider SDK·새 의존성이 없다. 직접 작성한 합성 Writer 사례 6개, 수동 기준선/후보 응답, 사람 검토 템플릿, 결정적 검사와 기준선 비교 차단 규칙을 제공한다. 모델 다운로드·추론·학습은 실행하지 않았으며 실제 운영 API 기준선도 이 파일에 포함하지 않는다.

작게 시작할 과업은 **사실을 보존한 문장 수정**이다. 상담 전체·추천 순위·일정 실행을 처음부터 자체 모델에 맡기지 않는다. 현재 사례에는 희망/부정/기간, 근거 부족, 비공개 자료 요청, 승인 없는 공개 경계가 들어 있다. 이는 scaffold 검증용 개발 데이터이며 계획한 고정 평가 세트나 독립 holdout을 완성한 것이 아니다.

| 순서                | 진행 조건                                                                                                                |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 지금: 평가 계약     | 합성만 사용, 사례군 분할, 입력·근거·응답 형식, 결정적 회귀, 사람 rubric, 안전 실패 즉시 차단                             |
| 실제 기준선 비교    | 독립 holdout 확보, 현재 API/후보의 동일 조건, 모델·prompt revision 기록, 블라인드 사람 평가, 표본 수와 한계 공개         |
| 후보·실험 비용 결정 | 모델/토크나이저/라이선스 revision 검토, 실행 장비 확인, 다운로드/추론/학습 비용 범위 결정                                |
| 제한 학습           | 프롬프트/규칙만으로 해결되지 않는 실패 확인, 학습 용도 권리·동의·철회/삭제 lineage, 평가와 분리된 데이터, 학습 예산 확정 |
| 제한된 교체 검토    | 기준선 대비 품질 퇴행 없음, 안전 실패 없음, 실제 전체 비용·지연 확인, 같은 권한·검증·영수증 계약, rollback 준비          |

운영 원문을 연구 폴더로 export하지 않는다. 운영 저장 동의는 학습 동의가 아니며, 공개 프로필 열람 권한은 상대 자료의 학습 권리가 아니다. 공급자 출력으로 대체 모델을 학습하는 권리도 별도로 확인한다. 실데이터 처리·보유 기간·새 공급자 전송은 이번 scaffold가 정하거나 허용하지 않는다.

오프라인 비교가 좋아도 운영을 자동으로 바꾸지 않는다. 합성 shadow와 승인된 제한 실험을 거쳐 **통과한 과업만** 별도로 검토한다. 코드의 `promotionAllowed: false`는 어떤 평가 입력에서도 유지된다. 지금은 테스트를 실행할 수 있는 연구 기반을 만든 것이며, 자체 모델 학습 성공이나 비용 절감·품질 우위를 달성했다고 주장하지 않는다.
