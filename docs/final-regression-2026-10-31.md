# After · 확정 UI 단순화와 전체 회귀 점검

## 결정과 범위

하단 탐색은 홈·소개 두 개를 유지한다. 가입/인증·프로필 준비, 여성 호감·남성 소개 열람, 상대 대화·개인 매니저 대화는 서로 다른 판단/정보 범위이므로 억지로 합치지 않는다. 사용자가 해야 하는 결정을 감추는 대신 중복 진입점과 상시 설명을 줄인다.

사용자는 흰 바탕·핑크 포인트를 유지하면서 보조 면을 웜 화이트 `#FAF9F6`로 변경하는 안을 승인했다. Apple은 용도별 시스템 배경을, Material은 surface/container 역할을 구분한다. 특정 회색이 금지 색인 것은 아니다. 애프터에서는 비슷한 중성 면이 입력창·아이콘·프로필 사실·매니저 답변 등에 반복되어 의미 구분이 약했다.

근거: [Apple의 grouped background](https://developer.apple.com/documentation/uikit/uicolor/systemgroupedbackground?language=objc), [Material의 색상 역할](https://m3.material.io/m3/pages/color-roles?s=m3). 본문/보조 글자·경고·오류의 색 역할과 다크 테마는 유지한다. 대비 검사를 실제 런타임 토큰으로 다시 계산한다.

## 이번에 줄인 것

- 마이페이지 상단 회원 카드와 메뉴의 중복 프로필 링크를 하나로 통합했다. 상단에 `프로필 보기`를 표시해 발견성을 유지한다.
- 전체 매니저 대화의 `대화·대화 설정` 상시 탭을 없애고 헤더의 설정 진입점 하나로 정리했다. 돌아오면 대화로 복귀한다.
- 상담 기록 삭제·동의 철회·기존 선호 관리는 대화 설정에서 함께 다룬다. 평소 대화 끝에 파괴적 행동을 계속 노출하지 않는다.
- 방금 보낸 비서 요청은 현재 상태·상대·열린 소개·약속·대화 세션이 그대로 유효할 때만 바로가기를 제공한다. 과거 기록이나 상태가 바뀐 요청은 기존 안전한 목록 경로로 돌아간다. 말만으로 결제·호감·약속을 확정하지 않는다.
- 중복 상담 안내와 마이페이지의 0회 반복 설명을 줄였다. 개인정보·공개 범위·금액·만남 상태·삭제 확인 문구는 유지했다.
- 반복된 차가운 회색 보조 면을 승인된 웜 화이트로 연결했다. 전체 배경을 아이보리나 핑크로 덮지 않는다.

## 발견 사항·잔여 게이트

- 프로필 진입을 합치는 과정에서 새 접근성 이름이 화면 문구를 포함하지 않는 문제를 자동 회귀가 발견했다. 불필요한 aria-label을 제거하고 실제 보이는 이름·프로필 보기 문구를 그대로 사용하도록 고쳤다.
- 설정에서 삭제를 확정하지 않고 대화로 돌아오면 확인창이 남고 작성창이 숨는 문제를 직접 재현했다. 화면 전환 시 미확정 편집/삭제 상태만 취소하며 작성 중인 대화와 기록은 유지하도록 수정했다.
- 수동 회귀 스크립트가 참여자의 5191 로컬 서비스와 포트를 공유하려던 문제를 발견했다. 회귀 전용 기본 포트 4294와 명시적 포트 설정으로 분리했다. 사용자의 실행 중 서버를 중단하지 않는다.
- 오래된 비서/수동 검사에는 예전 버튼명과 클라이언트 안내 전용 입력창, 외부 manual fixture 의존이 남아 있었다. 현재 지속 대화·합성 계정의 동의와 별도 포트로 맞추고, 서비스 API 진입과 유료 모델 호출을 구별해 실제 `ai_runs` 예약이 0인지 검증한다.
- 과거 로컬 마이그레이션 이력 누락은 이전 점검에서 기록했으며 이번 UI 변경에서 과거 이력을 임의로 보정하지 않는다.
- 외부 계약/키를 사용하는 통신사 실인증, 토스 실결제·실취소, 카카오 실제 발송은 자동 통과로 표시하지 않는다.
- 운영 MFA 재로그인·복구수단, 실제 기기 키보드·푸시, 장시간 운영 관찰은 사람/운영 확인과 구별한다. 이전 확인을 이번 코드 변경의 새 실기기 검증으로 바꾸어 기록하지 않는다.
- 실제 LLM 문구 만족도와 소개 후 체감 효과는 별도 합성 라이브 검증·베타 사용자 관찰이 필요하다. 이번 UI 수정은 모델·프롬프트·호출 횟수를 바꾸지 않는다.
- Impeccable의 전체 CSS 스캔에서 나온 기존 반경/글자 단계 advisory는 이번 변경으로 새로 추가된 항목이 아니므로, 무관한 스타일 변경이나 광역 ignore로 덮지 않았다.

## 의존성 보안 확인

운영 경로의 `seroval 1.6.9`에서 RegExp/TypedArray 직렬화 관련 중간 등급 경고를 확인했다.
[RegExp 직렬화 경고](https://github.com/advisories/GHSA-9wx9-5pv9-3349),
[TypedArray 생성자 경고](https://github.com/advisories/GHSA-f86p-h4j2-7qgj)를 확인하고
부모 라이브러리의 호환 범위 안인 `1.6.11`로 고정했다. 잠금 파일 변경은 seroval 한 패키지뿐이다.

실제 애플리케이션에서 공격이 성공했다는 의미는 아니다. 회귀는 고정된 합성 입력으로
HTML-sensitive 출력과 생성자 오염을 검사한다. 기존 설치본에서 2개 테스트가 실패하고,
공식 패치에서 일반 메시지 보존까지 3개가 통과하는 것을 확인했다. 잠금 정보와 실제
설치본이 다를 수 있으므로 설치 manifest와 실제 모듈 동작을 모두 검증했다.

패치 후 `npm audit --omit=dev`의 경고는 0개다. 전체 의존성에는 `minimatch`에서 파생된
개발 도구 영향 패키지 경고 17개가 남는다(중간 등급, high/critical 0). 서로 독립된
취약점 17개라는 뜻이 아니다. ESLint·Capacitor 등은 기존 minimatch API 의존과 메이저
호환성 검토가 필요하므로 `npm audit fix --force`로 강제 변경하지 않았다.
별도 개발 도구 업그레이드 백로그로 유지한다.

## 추가 확인과 최종 처리

넓은 회귀 결과를 확인한 뒤 발견/수정한 부분만 추가 검증했다. 설정 복귀 6개 조합,
패치 버전의 비서 API·수동 전체 흐름, 실제 프로필 저장·기존 기록 보존, 주요 화면
24개 및 최종 대화 4개 조합을 확인했다. 같은 화면을 반복한 수치를 고유 기능 수로
합산하지 않는다. 마지막 보안 회귀는 실제 로드한 모듈에서 수행한다.

수동 도구의 긴 브라우저 조작 뒤 Node의 유휴 Vite 소켓에서 ECONNRESET이 발생한
검사 오류는 새 연결·명시적 제한 시간으로 보완했다. 결제 변경 요청을 자동으로
재전송하지 않으며, 실제 PG 승인/취소 성공으로 해석하지 않는다.

[현재 기능/데이터 설계 점검](flow-data-audit-2026-10-31.md)과 함께 읽는다.
운영 기능 플래그를 이번 변경에서 켜지 않았고, 기존 로컬 참여자 기록을 유지했다.
임시 QA 프로젝트와 해당 테스트 프런트만 정리한다. main 병합은 사용자의 기존
승인에 따르며 CI·자동배포 완료와 별도로 보고한다.
