# 개인 비서 · 로컬 직접 테스트

2026-10-25 화면 개편 반영. 운영의 상담·기억·일정 비서는 켜지 않는다. 아래 주소·계정·시간 이동 도구는 로컬 Supabase 전용이다.

여성의 첫 호감 전부터 새 커플로 시작하고 모의 결제도 직접 누르려면 [새 커플 전체 흐름 테스트](assistant-manual-cycle.md)를 따른다. 기존 아래 계정은 진행 중인 기록을 그대로 유지한다.

## 1. 접속과 계정

- 앱: <http://127.0.0.1:5190/login>
- 남성: `assistant-male@verify.local` / 테스트 민준
- 여성: `assistant-female@verify.local` / 테스트 서연
- 운영자: `assistant-admin@verify.local`
- 세 계정 공통 비밀번호: `AfterLocal!2026`

위 비밀번호는 공개해도 되는 로컬 합성 계정용이다. 운영에서 재사용하지 않는다. 사진도 실제 사람이 아닌 `LOCAL TEST · SYNTHETIC PROFILE` 표식 이미지다. 실결제·문자·카카오 발송은 하지 않는다.

남성은 일반 브라우저, 여성은 시크릿 창이나 다른 브라우저를 사용한다. 같은 브라우저의 일반 탭끼리는 로그인이 공유되므로 남녀를 동시에 테스트하기 어렵다.

현재 시작 상태는 가입·프로필·사진 검수를 마치고 남성이 만남을 요청한 직후다. 여성의 시간 제안부터 직접 진행할 수 있으며, 상담 동의·기억·대화 기록은 비워 둔다. 가입/소개부터 시작하는 방법은 5절에 따로 있다.

## 2. 추천 확인 순서

### A. 나만의 상담 → 승인 기억

1. 남성 로그인 → 홈의 **비서에게 말해보세요** 입력창에 `첫 만남이 긴장돼요`를 입력한다. 상담 화면으로 문장만 이어지며 자동 전송하지 않는다. 직접 주소는 `/assistant?panel=chat`이다.
2. AI 전달·상담 보관 안내에 동의한다. 동의 전에는 상담 입력이 열리지 않아야 한다.
3. `첫 만남에서 긴장하면 질문만 많이 하게 돼요. 어떻게 시작하면 좋을까요?`라고 물어본다.
4. 답변은 나에게만 보여야 한다. 여성 창의 상담·프로필·채팅에 나타나지 않아야 한다.
5. **이 내용 기억하기**를 눌러 내용을 `첫 만남은 조용한 카페에서 짧게 이야기하고 싶어요.`로 바꾼다. 별도 체크 후 **승인하고 기억하기**를 누른다. 상담했다고 자동 기억하지 않아야 한다.
6. **기억 관리**에서 승인된 내용과 만료일을 확인한다. 다시 상담으로 돌아가 `내가 기억해 달라고 한 선호에 맞춰 첫 만남 장소를 추천해 주세요.`라고 물어본다.
7. 여러 번 대화한 뒤 화면을 나갔다 돌아오면 최신 대화를 볼 수 있어야 한다. 이전 질문의 기억 버튼을 누르면 승인 입력칸으로 이동하고, 헤더는 그대로 남아야 한다.

기억 수정·삭제와 동의 철회는 아래 E에서 마지막에 확인하는 편이 좋다. 기억을 수정/삭제하면 이전 내용이 다시 인용되지 않도록 상담 맥락도 비운다.

### B. 여성 시간 전달 → 남성 시간·장소 확정

1. 여성 로그인 → 홈의 **일정 정리** → **일정 정리하기** 또는 `/assistant-schedule`.
2. 3시간 이후~21일 이내의 날짜와 시간을 고른다. 예: 2026-10-26 19:00. 날짜가 지났다면 `npm run assistant:lab -- status`의 `suggestedDate`를 참고한다.
3. **전달 전 초안 보기**. 이때는 아직 상대에게 전달되지 않아야 한다. 날짜·한국 시간·상대를 확인한다.
4. 참석 확인 안내에 체크 → **승인하고 요청하기**. 성공 안내가 표시되어야 한다.
5. 남성 창 → `/assistant-schedule`. 여성이 제안한 시간을 선택하고, 장소에 `로컬 테스트 카페`를 적는다.
6. 초안을 확인하고 체크 → **승인하고 확정하기**. 두 계정의 대화/약속 화면에서 같은 일시와 장소를 확인한다.
7. 선택 사항: **일정 다시 준비하기**로 변경 초안을 만든다. 요청만으로 기존 약속이 바뀌면 안 된다. 상대의 기존 약속 화면에서 변경 수락까지 해야 바뀌어야 한다.

현재 일정 비서는 명시적 날짜·장소 입력 → 초안 → 건별 승인 방식이다. 채팅 한마디로 장소를 예약하거나 비서끼리 무승인으로 일정을 확정하는 단계는 아니다.

### C. 상대 맞춤 조언 → 참석 확인

1. 허용된 상대의 프로필에서 **대화 준비**로 진입한다. 홈의 **대화 팁** → **대화 준비하기**도 사용할 수 있다.
2. 공개 프로필 활용 안내에 동의 → 팁을 생성한다. 공개 취향에 근거한 대화 소재·질문·부담을 줄일 표현을 확인한다.
3. 상대 감정이나 MBTI 성격을 단정하지 않아야 한다. 개인 상담·승인 기억이 상대용 팁에 노출되면 안 된다.
4. 실제 시간을 기다리지 않고 참석 확인 구간을 보려면 터미널에서 다음을 실행한다.

   ```bash
   cd /Users/ys.choi/dev-private/after
   npm run assistant:lab -- checkin
   ```

5. 두 계정에서 홈의 **약속 보기** → 각각 **이 약속에 참석할게요**. 첫 번째 계정은 상대 대기, 두 번째 확인 뒤에는 두 사람 모두 확인한 상태여야 한다. 약속 상세에는 직접 대화·변경·취소가 그대로 있다.

`checkin`은 이 합성 커플의 확정 약속만 현재로부터 20시간 뒤로 옮긴다. 전체 알림/자동취소 작업은 실행하지 않는다. 실제 사용자는 확정한 날짜에 따라 진행한다.

### D. 만남 후 후기 → 다음 선호

1. 참석 확인 뒤 다음을 실행한다.

   ```bash
   npm run assistant:lab -- feedback
   ```

2. 출력된 `feedbackUrl`을 각 로그인 창에서 연다. 이 커플의 약속만 2시간 전으로 옮겨 실제 날짜를 기다리지 않게 한다.
3. 만남 결과·기억에 남은 점을 고르고 후기를 제출한다. 다시 열면 중복 제출 대신 제출 완료 안내가 나와야 한다.
4. **내 선호 직접 남기기**로 이동한다. 후기 원문은 자동으로 비서에게 전달되거나 기억되지 않아야 한다.

시간을 앞당겨 후기 화면을 보는 것과 자정 자동 넛지 검증은 별개다. 자동취소·티켓 복구·경고·자정 후기 알림은 별도의 합성 전체 사이클 검사에서 확인했으며, 수동 테스트 도구는 전체 회원 대상으로 작업을 돌리지 않는다.

### E. 삭제·철회·실패 상태

- 기억 수정/삭제: 대상 기억과 상담 맥락이 지워져야 한다. 여성 계정에는 영향이 없어야 한다.
- **상담 동의 철회·전체 삭제**: 재진입하면 다시 동의해야 한다. 예전 기록이 재등장하면 안 된다.
- 과거 날짜나 장소 미입력: 구체적인 안내와 비활성 버튼을 확인한다.
- 일정 초안 취소: 약속 자체를 취소하는 것이 아니어야 한다.
- 잠시 오프라인: 성공으로 위장하지 않고 재확인 안내가 나와야 한다. 결과가 불명확할 때 반복 클릭으로 재실행하지 않는다.
- 운영자 `/admin` 및 `/admin/system`: 작업·성공/실패·처리 상태를 확인한다. 상담·기억 원문을 볼 수 없어야 한다.

실제 AI는 로컬 환경 파일의 Anthropic 키를 사용한다. 상담·대화 준비를 누를 때 모델 비용이 발생한다. 먼저 위 질문 1~2건으로 확인하고, 대량 반복하지 않는다. 일일 한도/사용 원장은 초기화 도구로 지우지 않는다.

1. 긴 상담을 다시 열면 처음 대화부터 보이던 문제 → 최초 진입/내가 보낸 답변만 최신 위치로 이동. 백그라운드 갱신은 과거 대화 읽기를 방해하지 않는다.

3. 띄어쓰기 없는 긴 기억이 면 밖으로 넘치던 문제 → 긴 단어도 줄바꿈.

### 2026-10-25 오렌지 홈 개편

- 하단은 홈·소개, 상단은 상점(남성)·나. 알림은 나 화면에서 확인한다.

## 4. 서버를 다시 켜야 할 때

현재 로컬 앱과 Edge 서버를 실행해 둔다. Mac/터미널이 종료되었다면 아래 순서로 각각 실행한다.

```bash
cd /Users/ys.choi/dev-private/after
npx supabase start
npm run assistant:lab
```

별도 터미널 1:

```bash
cd /Users/ys.choi/dev-private/after
npx supabase functions serve --env-file supabase/functions/.env --no-verify-jwt
```

별도 터미널 2:

```bash
cd /Users/ys.choi/dev-private/after
npm run assistant:lab:dev
```

`assistant:lab:dev`는 로컬 CLI에서 확인한 Supabase 주소·키로만 Vite 5190을 띄운다. 결제창 클라이언트 키를 비워 상점에서 결제창을 실행하지 못하게 하며, 테스트 티켓으로 진행한다. 운영 키를 복사하지 않는다. CLI의 `--no-verify-jwt`는 로컬 게이트웨이 설정이고, 각 함수의 사용자 인증/권한 검사는 유지한다. 포트가 이미 사용 중이면 기존 서버를 확인하고, 다른 서비스의 프로세스를 종료하지 않는다.

## 5. 다시 시작하거나 소개부터 보고 싶을 때

```bash
# 현재 진행·기억을 유지하면서 로컬 기능을 켜고 상태 확인
npm run assistant:lab
npm run assistant:lab -- status

# 이 합성 계정의 진행을 비우고 여성 시간 제안 직전부터 다시 시작
npm run assistant:lab -- reset --schedule

# 소개부터: 여성 호감 전달 완료 + 남성 소개 도착 상태, 테스트 티켓 각 1장
npm run assistant:lab -- reset

# 테스트 종료 시 로컬의 세 기능만 끄기
npm run assistant:lab -- off
```

`reset`은 이 도구가 소유한 남녀 계정의 상담·기억·후기·약속·테스트 티켓 등 진행 기록을 삭제한다. 이 계정이 다른 프로필과 소개/큐/추천 초안으로 연결되면 자동 초기화를 거절한다. 다른 회원 데이터와 AI 사용/운영 감사 원장은 삭제하지 않는다. 사용자 로컬 DB 전체를 초기화하는 `e2e-seed`를 대신 실행하지 않는다.

소개부터 시작하면 남성이 소개 티켓으로 프로필을 열고 기존 만남 요청/후보 시간 제안을 진행하고, 여성이 요청을 확인한다. 이 경로는 기존 후보 시간 방식도 사용하므로, B의 여성 우선 시간 입력 화면과 다를 수 있다. 가입부터 확인하려면 별도의 합성 이메일로 새로 가입한다. 준비된 세 계정은 본인/회사 인증을 우회한 완료 fixture이므로 실제 인증 성공의 근거가 아니다.

운영의 `assistant_chat_enabled`, `assistant_memory_enabled`, `assistant_schedule_enabled`는 이 문서나 로컬 명령으로 켜지지 않는다. 운영 활성화는 별도 검증·승인 후 진행한다.
