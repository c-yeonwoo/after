# 비서 중심 전체 흐름 · QA 결과

2026-10-25 · 설계: [비서 엔지니어링 아키텍처](assistant-engineering-architecture.md).

## 구현한 범위

- 홈과 비공개 상담이 같은 규칙 라우터를 사용한다. 가입·인증, 프로필 준비/수정, 소개·호감, 티켓·구매, 일정, 기억 관리, 안전/문의의 다음 행동을 연결한다.
- 비서 안내를 가입, 인터뷰의 전 단계, 공개 프로필 확인, 소개, 만남 요청/응답, 날짜 선택, 상점·결제에 적용했다. 기존 폼·필수값·본인 확인·저장/차감/PG 승인 절차는 유지했다.
- 자유 입력은 작업의 시작점이지 실행 승인이 아니다. 채팅만으로 호감·거절·티켓 차감·결제·예약·전송하지 않는다. 기존 구조화된 화면에서 대상을 확인하고 직접 승인한다.
- 서비스 질문은 클라이언트뿐 아니라 Edge 직접 호출에서도 모델 없이 답한다. 실제 진행 상태는 인증 세션의 상태 코드로, 구매 안내는 인증된 본인의 성별로 판정한다. 모델에 전체 홈 응답·상대 정보·추가 프로필을 보내지 않는다.
- 일반 자유 상담의 기존 Sonnet 생성+별도 프롬프트 검수는 유지한다. 새 모델·무한 에이전트·자동 재시도·전역 상담 캐시를 추가하지 않았다.

전체 브라우저 두 엔진·깨끗한 DB 릴리스 게이트는 `.github/workflows/release.yml`에서 같은 커밋을 재검증한다. 이 문서는 운영 반영이나 외부 계약 완료의 영수증을 대신하지 않는다. 실제 배포 버전은 해당 PR의 main 배포 실행과 `app-version`으로 확인한다.

새 design ignore/suppression은 추가하지 않았다. 문서 검수에서 sidecar의 비활성 전송 버튼 예제가 opacity를 사용하지만 실제 버튼은 muted 색상을 쓰는 기존 차이를 확인했으며, 이번 범위 밖의 사전 드리프트라 수정하지 않았다.

## 이번 검수에서 수정한 결함

1. 프로필 준비가 대화 준비로 잘못 분류되던 우선순위 수정. 상대를 명시한 “상대 프로필을 바탕으로 대화 주제 추천”은 별도로 대화 준비로 분류한다.
2. 결제 질문을 일괄 고객센터로 보내던 동선 수정. 현재 이용 조건과 상품은 상점/실제 주문 화면에서 확인하며 여성에게 구매를 유도하지 않는다.
3. 일정 비서 OFF에서 `schedule_selection`을 빈 확정 약속 목록으로 보내던 경로 수정. 기존 만남 준비 화면의 날짜 선택으로 연결한다.
4. “휴대폰 인증이 안 돼요”, “이메일 인증이 안 와요”, “만남을 취소하고 싶어요”가 자유 상담으로 빠지던 반례 수정.
5. Edge를 직접 호출한 대화 팁 질문도 모델 없이 안내한다. 여성 구매 안내도 클라이언트가 아니라 인증된 본인 데이터로 판정한다.
6. 소개 열람 버튼의 중복 전송을 잠그고, 실패/계정 전환/결과 불명 상태에서 실제 상태를 다시 읽도록 했다.

## AI 비용 측정

이번 합성 자유 상담 2건의 `assistant-private-v2-workflow` 원장 합계는 Sonnet 입력 **3,705**, 출력 **469**토큰이다. 두 건 모두 생성과 검수가 포함되어 있고 최장 처리 시간은 약 4.95초였다. 서비스 질문·이동 안내·안전 거절은 원장을 증가시키지 않았다.

현재 [공식 Sonnet 가격표](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)의 일반 입력 $2/백만, 출력 $10/백만 기준 단순 환산은 두 건 합계 약 **$0.0121**이다. 실청구·세금·공급자 요금 변경과 다를 수 있고 모든 질문의 비용을 보장하는 수치는 아니다. 24시간 10회 AI 실행 제한은 공급자 USD 청구 상한과는 다르다. 짧은 프롬프트에 캐시를 무조건 추가하거나 품질 검수를 빼서 비용을 줄이지 않았다.

## 환경 차이와 남은 확인

기존 사용자 테스트 DB에는 과거 AI 원장과 성숙 코호트가 있으며 비서 기능을 ON으로 설정해 두었다. 초기 전체 SQL 검사는 빈 데이터/기본 OFF를 가정한 s36/s39/s65c/s96에서 실패했다. 테스트를 완화하거나 기존 데이터를 지우지 않고, 기본 OFF인 독립 DB에서 현재 67개 파일 그대로 실행해 975개 통과를 확인했다. 두 DB는 서로 다른 프로젝트·포트다.

원래 로컬의 사용자 테스트 계정과 진행 중 약속은 유지한다. `/login`의 `assistant-male@verify.local`, `assistant-female@verify.local`, 공통 로컬 전용 암호 `AfterLocal!2026`로 이어서 테스트할 수 있다. 앱 주소는 `http://127.0.0.1:5190`이다.

아래는 구현/합성 QA 통과와 별개의 상태다.

- 운영 비공개 상담·기억·일정 실행은 **OFF 유지**. 고지/동의·제공자 조건·운영 복구를 검토하고 사용자가 활성화를 승인하기 전 켜지 않는다.
- 실결제/환불, 통신사 성인인증, 카카오 실제 발송은 이번 QA에서 실행하지 않았다.
- 실제 기기의 소프트 키보드·터치·설치형 PWA는 새 버전에서 사용자 확인이 필요하다.
- 실제 LLM 프로필 작성·상대 맞춤 팁의 전용 파이프라인은 이번에 변경하지 않았다. 생성 UI는 결정론적 대역으로 검증했고, 자유 상담 2건의 실모델 성공을 프로필 생성 품질의 추가 검증으로 과장하지 않는다.
- 실제 참가자 상담 만족도, 안전 실패율·지연·비용의 장기 관찰은 베타 운영 항목이다.
