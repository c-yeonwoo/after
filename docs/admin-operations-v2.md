# 애프터 1인 운영 콘솔 v2

## 목표

운영자가 여러 화면의 숫자를 해석해 할 일을 만드는 대신, **오늘 처리할 일 → 실제 조치 → 자동화 확인 → 감사 기록**을 한 흐름으로 끝내게 한다.

운영 원칙은 세 가지다.

1. 사용자 경험이 멈추는 일을 가장 먼저 보여준다.
2. 되돌릴 수 없거나 사람의 판단이 필요한 결정은 자동 실행하지 않는다.
3. 반복 작업은 초안·대기열·재시도로 자동화하되 모든 수기 조작에는 사유를 남긴다.

## IA

| 영역          | 메뉴                  | 운영 질문                       |
| ------------- | --------------------- | ------------------------------- |
| 오늘          | 운영 홈               | 지금 무엇부터 처리해야 하나?    |
| 매칭 운영     | 큐레이션, 만남        | 소개 공급과 일정 진행이 막혔나? |
| 회원과 안전   | 회원, 사진 검수, 신고 | 가입·신원·안전 이슈가 있나?     |
| 거래와 시스템 | 주문, 시스템          | 돈과 자동화가 정상인가?         |

데스크톱은 그룹형 사이드바를 사용하고, 모바일은 같은 메뉴를 가로 탐색으로 제공한다. 사이드바의 회원 검색은 이름 또는 회사 이메일로 회원 목록을 바로 연다.

## 이번에 구현한 기능

### 운영 홈

- P0: 노쇼 SLA 초과, 알림 최종 실패, 미처리 콘텐츠 신고
- P1: 일정 확정 지연, 사진 검수, 수동 주문 발급, 큐레이션 대기
- 건수를 누르면 해당 필터가 적용된 실제 처리 화면으로 이동
- 마지막 갱신 시각과 수동 새로고침
- 처리할 일이 없을 때 명확한 정상 상태 표시
- 전체 규모·수급·품질 지표는 필요할 때만 펼쳐 보는 상세 영역으로 이동

### 큐레이션

- 빈 전송 슬롯을 오래 기다린 호감 순으로 자동 채우는 **검토 초안**
- 프로필 확인, 순서 변경, 사유 입력, 저장은 계속 운영자가 수행
- 유료 소개의 신뢰를 훼손할 수 있는 완전 자동 매칭은 적용하지 않음

### 시스템 운영

- 알림 발송 대기·최종 실패와 결제 모드 요약
- 최종 실패한 알림의 대상, 종류, 시도 횟수, 오류 원인 확인
- 설정 복구 뒤 실패 알림 일괄 재시도 및 건별 감사 기록
- 핵심 cron 작업의 등록·활성·최근 실행 결과 확인
- AI 기능의 모델, 프롬프트 버전, 성공 여부, 지연, 토큰 확인
- 프로필/대화 원문을 저장하거나 노출하지 않는 AI 관측
- 모든 최근 운영자 조작을 한곳에서 확인

## 의도적으로 보류한 기능

- **어드민에서 회원 계정 직접 생성**: Auth의 service role이 필요한 서버 전용 기능이며, 신원 확인·동의 증빙·개인정보 책임 범위를 먼저 결정해야 한다.
- **완전 자동 매칭**: 현재 상품 약속은 사실성과 사람 검토가 포함된 소개다. 초기 데이터가 부족한 상태에서 자동 순위가 결정을 대신하면 품질 원인을 학습하기 어렵다.
- **자동 정지·자동 환불**: 안전 및 금전 조치는 오탐 비용이 크므로 운영자 확인과 사유 기록을 유지한다.
- **광범위한 개인정보 내보내기**: 1인 운영 편의보다 유출 위험이 더 크다. 필요성이 확인된 최소 데이터만 별도로 설계한다.
- **어드민 2단계 인증**: 출시 보안상 중요하지만 현재 인증 공급자와 계정 정책 결정이 선행되어야 한다.

## 일일 운영 루틴

1. 운영 홈에서 P0를 모두 처리한다.
2. 사진 검수와 수동 주문을 처리한다.
3. 큐레이션 대기 호감의 전송 슬롯 초안을 검토·저장한다.
4. 만남 일정 지연을 확인한다.
5. 시스템에서 알림 실패와 자동화 상태를 확인한다.

처리할 일이 없다면 시스템 정상 여부와 성별·권역별 수급만 확인하고 종료한다. 숫자 자체를 늘리는 활동보다 실제 만남이 멈춘 지점을 먼저 해결한다.
