# After 에이전트 회사 — 수동 운영 시작 안내

설치 확인: 2026-10-18. 로컬 Paperclip 0.3.1, 회사 `After` / `AFT`.

**[After 대시보드 열기](http://127.0.0.1:3100/AFT/dashboard)**

현재는 조직·지침·스킬·초기 작업과 수동 실행 환경을 구성한 상태다. 자동으로 회사를 운영 중인 것은 아니다. 담당자 8명 모두 `idle / ready / 오류 없음`을 확인했다. 업무 실행 이력은 0회이며, 초기화 과정의 짧은 모델 hello 연결 검사는 별도다.
기존 MAKELI/첫굿즈 회사 설정은 변경하지 않았다. 같은 로컬 서버를 사용하므로 서버가 꺼지거나 Mac이 잠자면 이 회사도 사용할 수 없다.

총괄 아래 7개 전문 역할. 담당 스킬만 배정했으며 공통 Paperclip 스킬은 서버가 추가한다.
14개 전문 스킬의 원본 및 참조 파일을 로컬 소스에서 가져왔다. 스킬 상태 `configured`는 다음 실행에서 런타임에 연결될 예정이라는 뜻이다.
등록되지 않은 LazyCodex/taste-skill/korean-privacy-terms/ui-ux-pro-max/understand-anything은 설치되어 있다고 주장하지 않는다.

## 지금 실행하는 순서

1. 대시보드에서 `After` 회사인지 확인한다.
2. 프로젝트 **After · 제품 개발과 베타 운영**에서 `00 · 수동 운영 시작과 연결 검증`을 연다.
3. 총괄 담당자의 수동 실행을 요청한다. 첫 요청은 다음과 같이 제한한다.

   > 이 작업의 역할 지침과 저장소 문서를 읽고 현재 제품 상태, 우선순위 3개, 필요한 도구 연결을 보고해줘. 파일 수정·PR·회원 데이터 조회·다른 에이전트 호출·스케줄 설정은 하지 마. 사용할 모델과 스킬을 실제 확인한 범위에서 적어줘.

4. 모델 로그인/런타임 오류가 있으면 여기서 멈춘다. API 키를 티켓이나 채팅에 붙이지 않는다. 이 구성 과정에서는 새 키를 등록하거나 업무를 실행하지 않았다. 기존 로그인으로 초기 연결 검사만 수행했다.
5. 결과를 확인한 뒤 제품·디자인·AI를 한 명씩 직접 실행한다. 인계는 티켓으로 남기되 다음 담당자는 자동으로 깨우지 않는다.
6. 구현안을 승인하면 개발 작업용 독립 worktree, 필요한 쓰기/네트워크 권한을 설정하고 그 작업을 직접 실행한다. 현재 기본 `read-only`에서는 코드 수정·빌드 산출물 쓰기가 제한된다. sandbox 전체 해제는 기본 해결책이 아니다.
7. QA를 별도로 직접 실행한다. 작성자가 자신의 변경을 최종 승인하지 않는다. 수락 기준·필수 CI·운영 버전 확인까지 통과한 변경만 머지한다.

초기 티켓은 인터뷰 질문 중복 개선 → 프로필 UX/AI 품질 검토 → 구현 준비 → 독립 QA 순서다. 운영·마케팅 검토도 별도 티켓으로 배정했다.

## 적용된 실행 제한

- 회사 활성, 에이전트 대기 상태. **예약 실행 OFF, 할당/멘션 자동 깨우기 OFF**.
- 이 로컬 Paperclip에는 사용자 수동 호출만 예외로 허용하는 확장이 있다: `allowExplicitManualWake=true`. 일반 배포판으로 이전 시 이 동작을 재검증해야 한다.
- Sol(`gpt-6-sol`) / high 설정. Paperclip의 기본 hello 연결 검사는 통과했다. 실제 장기 업무·도구 인계 품질은 첫 수동 작업으로 검증한다.
- 에이전트별 15분 타임아웃, 동시 실행 1개, 일일 실행 2회. 회사 전체 동시 실행 제한은 별도 강제하지 않으므로 대표가 한 명씩 실행한다.
- 신규 에이전트 생성은 대표 승인 필요. 각 에이전트의 채용·스킬 생성 권한 OFF.
- 광고 집행·콘텐츠 게시·회원 메시지·실결제/환불·제재·운영 DB 변경은 별도 승인 대상이다. **정책 지침이며 모든 외부 API에서 기술적으로 강제된 권한 제어는 아니다.**
- `budgetMonthlyCents=0`은 승인한 유료 예산이 없음을 기록한 값이다. 무료·공급자 강제 지출 상한을 의미하지 않는다. 수동 실행도 Codex 계정 사용량을 소모한다.
- 읽기 전용 샌드박스는 로컬 비밀 파일 읽기나 외부 서비스 접근까지 전부 격리하는 보안 컨테이너가 아니다. 실제 무인 운영 전에 전용 실행 계정/컨테이너·최소권한 자격증명·네트워크 제한이 필요하다.

## 구성 파일과 재현

- `ops/paperclip/company.json`: 역할·스킬 원본·모델 설정
- `ops/paperclip/POLICY.md`: 공통 정책 (현재 지침의 원본)
- `ops/paperclip/provision.mjs`: 로컬 신설/중단된 초기 설정만 복구. 실행 중인 기존 회사 덮어쓰기 금지.
- `ops/paperclip/verify.mjs`: 최초 구성 전용 읽기 검증. 실제 작업 시작 후에는 0실행/8백로그 조건이 달라지므로 실패가 정상일 수 있다.

```sh
node ops/paperclip/provision.mjs --check
# 신규 또는 paused 상태의 이 하네스 소유 회사만 대상; 초기화 hello 검사로 구독 사용량이 소모될 수 있음
node ops/paperclip/provision.mjs --apply --enable-manual
node ops/paperclip/verify.mjs
```

스킬 경로는 이 Mac의 설치 버전에 맞춰 기록되어 있다. 다른 컴퓨터에서는 원본 경로/라이선스/도구 의존성을 확인하고 수정해야 한다.
역할 지침은 회사 생성 시 Paperclip의 관리 지침으로 복사된다. 원본 파일 수정이 기존 에이전트에 자동 반영되지는 않는다. 불일치 시 초기화 스크립트는 덮어쓰지 않고 실패한다.
이 구성 변경은 After 앱의 사용자 기능·운영 DB·Cloudflare 설정을 변경하지 않는다.

실행 파일은 After 전용 `~/.local/share/after-harness/codex-runtime/node_modules/.bin/codex`다. `@openai/codex@0.163.0`을 별도 설치했다. 데스크톱 앱의 알파 CLI는 현재 Paperclip 버전 검사에서 거부되어 사용하지 않는다. 기존 회사/앱 CLI는 변경하지 않았다.
