# Eclipse 출시 백로그

최종 갱신: 2026-09-20

이 문서는 지금 코드만으로 안전하게 끝낼 수 없는 출시 항목과, 제품 책임자의
명시적 결정이 필요한 항목만 남긴다. `docs/HANDOFF.md`는 더 이상 갱신하지 않는다.

## 외부 의존 — 공급자/전문가 확정 뒤 진행

- **본인인증**: 휴대폰 본인확인 또는 신분증·얼굴 대조 공급자 선정, 비용·보관 범위,
  실패/재시도/탈퇴 시 삭제 정책 확정. 현재 제품이 보장하는 것은 회사 이메일
  소유 확인이며, 이를 실명·재직 보장으로 표현하지 않는다.
- **PG 실결제·실환불**: 주문 생성 → 승인 웹훅 검증 → 티켓 발급 → 거절/만료/탈퇴
  환불의 멱등성까지 샌드박스에서 검증. 현재 `ticket_orders`와 `tickets`의 내부 상태
  전이는 실제 카드 승인·취소가 아니다.
- **법률·사업자 검토**: 통신판매/전자상거래 표시, 청약철회·환불, 개인정보 처리방침,
  위치·민감정보 취급, 미성년자 차단, 신고/제재 고지, 사업자 정보와 고객문의 채널을
  변호사/노무·세무 전문가와 확인. 확인 전에는 존재하지 않는 사업자 정보나 보장을
  화면에 쓰지 않는다.

## Astra 결정 필요 — 구현 전에 중단

- **노쇼 제재 강도**: 현재는 상대가 24시간 무응답이면 신고가 사실로 확정되고 영구
  이용 제한된다. `무응답=영구 제한`을 유지할지, 임시 제한 → 운영자 확인 → 영구 제한의
  단계형으로 바꿀지 결정해야 한다. 오탐 비용과 운영 부담이 모두 커 Sol 구현 판단으로
  바꾸지 않는다.
- **안전 운영 기준**: 신고 누적 임계치, 즉시 숨김 범위, 소명 기한, 재가입 차단 키,
  긴급 상황 대응 문구와 운영 SLA를 확정한다.
- **최종 네이밍/리브랜딩**: P0 안정화와 한 사이클 검증 뒤 결정한다. 결정 전에는
  `Eclipse/이클립스`를 유지하고 대규모 에셋 교체를 하지 않는다.

## 출시 직전 사람 확인

- 실제 회사 메일 가입 1회, 개인 알림 메일 확인 1회
- 여성 평가 → 운영자 큐레이션 → 남성 소개 열람 → 만남 요청 → 일정 확정 → 채팅 →
  후기까지 두 계정으로 완주
- 소개 도착, 요청 도착, 답변 도착, 확정, 노쇼 응답 요청 메일을 실제 수신함에서 확인
- PG·본인인증·법률 항목이 완료되기 전에는 유료 공개 모집 대신 제한된 무료/수동 POC로 운영
