# 토스페이먼츠 만남업종 추가 심사 — 실행 상태 (2026-10-16)

이 문서는 토스 담당자 메일의 추가 요청을 실제 서비스/증빙과 대조한 내부 실행표다. **현재 결제경로 PPT를 최종 심사용으로 보내면 안 된다.** 성인 본인확인 창과 그 서버 검증을 아직 갖추지 않았으며, 기존 PPT에는 고객상담·티켓 사용내역 화면도 없다.

## 성인 본인확인 구현 기준

1. 공급자와 본인확인 서비스 계약·채널 개설. 후보: 휴대폰 본인확인을 제공하는 포트원 V2 연동(다날/KCP 등). 포트원 [공식 연동 문서](https://developers.portone.io/opi/ko/extra/identity-verification/readme-v2)는 브라우저 요청 후 **서버가 인증 결과를 조회**하도록 한다. 공급자/수단별로 제공되는 정보가 다르므로 계약 전에 생년월일·중복가입 식별값 제공 여부를 확인한다.
2. 브라우저의 “성공” 값이나 자가 입력 생년월일을 믿지 않고, 서버가 인증 ID로 공급자 API의 `VERIFIED` 상태와 `verifiedCustomer.birthDate`를 조회해 연령을 판단한다. 최소 정보만 저장하고 원본 주민번호·신분증 이미지는 받지 않는다.
3. DB에 인증 완료 시각·공급자 거래 ID·필요 최소한의 중복가입 식별값을 기록한다. 재시도/중복/만료/탈퇴/재가입과 기존 회원 전환을 테스트한다.
4. 가입만 막아서는 안 된다. 기존 회원도 인증하지 않았다면 **소개 노출·티켓 주문/사용·결제**에서 서버가 거절해야 한다. 관리자 수기 발급과 무료 베타 경로도 우회가 없어야 한다.
5. 개인정보 처리방침의 위탁/보유기간/제3자 제공 및 기존 회원 고지·재동의를 법률 검토 후 반영한다. 인증 완료·거절 화면을 실제 공급자 테스트 환경에서 캡처한다.

## 새 결제경로 PPT 캡처 순서

기존 웹용 가이드와 `deliverables/toss-payment-flow-sandbox-evidence-2026-10-10-v3.pptx`의 실제 결제 흐름을 재사용하되, **한 주문의 일관된 실화면**으로 다시 캡처한다. 최종 파일에 합성 인증창·가짜 응답·실제로 없는 제재 기능을 넣지 않는다.

1. 공개 첫 화면/서비스명 → 사업자정보(사업자등록증의 동·층·호수까지 동일), 고객 문의 링크.
2. 로그인/가입 → **외부 성인 본인확인 요청창과 완료 화면**. 테스트 표시·개인정보는 심사자에게 필요한 범위만 남기고 가린다.
3. 상품 상세(가격, 티켓이 제공하는 서비스, 12개월 유효기간) → 환불/청약철회 약관 → 주문 확인.
4. 토스 결제창 → 승인 완료 → 결제 내역 → **티켓 발급·사용·반환 이력**. 샌드박스 거래임을 슬라이드에 명시한다.
5. 고객지원의 **문의 접수 화면** → 문의 내역/답변 화면. 운영자 미답변 큐/답변 화면은 보조 증빙으로 붙인다.
6. 신고/차단 UI와 운영자 판정·제재 화면은 악용방지 설명의 보조 슬라이드로 넣는다. 실제 계정의 대화·신원은 가린다.
