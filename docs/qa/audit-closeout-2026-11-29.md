# 11월 22일 애프터 진단 후속 점검

진단 당일 운영 집계는 여성 0명·남성 1명이 소개 가능했고 최근 28일 소개·확정 약속이 각각 0건이었다. 11월 29일의 수급은 운영 홈에서 다시 읽어야 한다. 실사용 만족도와 채산성은 아직 계산할 표본이 없다.

| 진단 항목 | 현재 구현과 검증 기준 | 운영에서 남은 확인 |
| --- | --- | --- |
| 랜딩과 가입 | 첫 화면의 시작 버튼을 유지하고 가상 소개에서 상대의 말, 매니저의 이유, 후보 시각 두 개를 함께 읽는다. 개인 이메일 허용, KCP 직접 가입, 카카오 후 본인확인 경로와 실기기 미리보기를 분리했다. | 초대 전 첫 방문자에게 10초 뒤 무엇을 맡길 수 있는지 묻는다. KCP 운영 인증은 아래 순서로 실기기에서 확인한다. |
| 프로필과 정보 처리 | 가입 후 프로필 준비·직접 작성·임시저장·충돌 복구·공개 전 확인이 있다. 종교 입력·노출·기존 저장값이 제거됐다. 선택 상담 동의와 가입 동의를 분리한다. | AI 공급자 계약과 실제 보유·삭제 설정, 목적·국외 이전 고지는 대표가 처리 범위와 대조한다. |
| 첫 소개와 응답 | 운영 작업함과 연결된 대기 단계·다음 확인 시각, 공개 답변과 후기 선호에 기반한 소개 이유, 선호에 따른 후보 우선순위가 있다. 여성에게 호감 후 상대에게 보이는 범위와 앱 알림 위치를 안내한다. 남성은 프로필 열람과 날짜 조율을 따로 선택한다. | 첫 초대 여성·남성의 대기와 ‘소개 이유가 와닿았는지’를 운영 홈에서 분자·분모와 함께 확인한다. 닫힌 웹의 외부 알림 수신은 별도 실기기 확인이 필요하다. |
| 약속과 후기 | 확정·취소, 무응답과 알림 미열람, 티켓 복구, 선택 후기와 다음 소개 반영을 구분한다. 초대 1차의 실제 만남은 양측 후기와 서버 접수 시각으로 센다. | 3명씩 초대한 뒤 첫 48시간 작업함, 14일 관찰, 희망자 인터뷰를 기록한다. |
| 티켓과 판매 | 한 판매 스위치를 랜딩과 상점이 함께 읽는다. 조회 오류는 무료로 표시하지 않는다. 소개 열람과 만남 조율의 사용 시점, 티켓 반환과 만료일을 결제 전·결제 완료·약관에서 확인할 수 있다. 무료 모드에는 예정 가격을 광고하지 않는다. 사업자 정보는 랜딩 하단에서도 확인한다. | 공개할 고객센터 번호를 배포 변수 `PUBLIC_BUSINESS_PHONE`에 설정한 뒤 랜딩·약관의 실제 표시와 사업자 증빙을 대조한다. 심사 목적으로만 받은 번호는 전용하지 않는다. PG 서면 승인, 실제 인증·결제 증빙과 철회 조건을 확인한 뒤 별도 유료 전환을 결정한다. |
| AI 소개 품질 | 합성 공개 답변 6개의 방향 있는 30쌍으로 주체·정확한 인용·사적 소재 제외를 오프라인 검사한다. 예산 실패와 타임아웃은 별도 transport 회귀에서 검사한다. | 30쌍의 실제 생성 문장을 원문과 대조해 희망/경험, 빈도, 근거 없는 공통점·확정 약속, 비공개 정보 노출을 평가한다. 오류는 원인과 수정 여부로 기록하고, 참가자에게 자신의 말로 소개 이유를 되짚어 달라고 요청한다. 읽기 전용 해설에 대한 별도 개통 판단이다. |
| 관리자·안전 | 중요 조치 MFA 서버 가드와 운영 작업함이 있다. 운영 알림함 기록·앱 읽음·외부 도달은 각각 구분한다. | 보조 수단 또는 프로젝트 소유자 복구 경로 확인 → 별도 브라우저 재로그인·AAL2 확인 → 중요 작업 MFA 적용 확인. 파일럿 중 비공개 노출·미성년 의심 미처리·중복 차감 미복구·긴급 신고 기한 초과가 생기면 모집을 멈추고 해당 큐부터 처리한다. |
| 사업·채널 | 1차 모집은 여성·남성 각 3명이다. 서로 가능한 동네·시간을 모집에 활용하며 가입 권역이나 직장 자격을 추가하지 않는다. | 운영 시간·불발 비용·양측 모집비·실제 결제자를 기준으로 재평가한다. 유료 광고와 앱 마켓은 각각의 승인 이후 진행한다. |

운영 순서와 집계 기록은 [첫 초대 베타](../invite-beta-first-cohort.md), 인증 개통 절차는 [KCP 직접 연동](../kcp-direct-identity.md), 유료화 제출 항목은 [토스 심사 초안](../toss-payments-merchant-application.md)에 있다. 실기기 결과, 계약 승인, 사람의 판단은 코드 병합으로 대체할 수 없다.
