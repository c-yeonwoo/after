# 애프터 무료 초대 베타 마감 점검

2026-10-17. 범위: 현재 할 수 있는 제품/운영 코드와 회귀 검증. 카카오 발송·실결제·통신사 본인확인은 대표 요청으로 후속 분리. HANDOFF는 수정하지 않는다.

## 오픈 판단

**소규모 무료 초대 베타는 조건부 GO, 유료 공개 출시·대규모 광고는 NO-GO.**

조건은 실제 기기 스모크, 실제 회사 메일/SMS 수신, 대표 운영 관리자 MFA/복구수단 확인이다.
자동화는 이 사람 확인을 대신하지 않는다. AI 품질의 10회 실호출/사용자 만족도 평가도 미완료이므로
첫 5–8명은 인터뷰 동행/소개글 승인 관찰을 하고 확대 여부를 판단한다.
기술 점검 통과를 법률·PG 심사·실명/성인 확인 완료로 표현하지 않는다.

## 이번 구현과 안전 기준

| 항목 | 실제 처리 |
| --- | --- |
| 약속 전 직접 확인 작업 | D-4h부터 양측 참석 미확인·한쪽 미확인·이전 약속을 작업함에 생성. 조회시각·30초 갱신·대기/다음 확인 시각 제공 |
| 운영 연락 | `/settings`에서 별도 선택 동의, 초기 미동의. 인증된 번호만 연락 작업에서 조회, 관리자 권한/기존 MFA 정책·조회 감사 기록 적용. 상대에게 번호 미공개 |
| 직접 확인 완료 | 운영자가 **실제로 두 사람에게 확인한 경우에만** 체크+사유로 완료. 개인 참석 탭을 위조하지 않고 `운영팀 확인`으로 구분. 미확인/연락 시도는 완료가 아님 |
| 반복 경고 | 검토 완료는 현재 경고 묶음만 덮고, 새 경고가 생기면 작업 재개. 원래 경고 이력 보존·자동정지 없음 |
| 일정 변경 | 확정 전은 기존 조율, 확정 후는 새 시간 제안→상대 동의→버전 증가. 거절/철회/만료는 기존 약속 유지. 3시간 뒤부터 3주 이내 평일 저녁, 하루 제안 3회 제한 |
| 일정 정합성 | 동의 전 시간/장소/티켓 불변, 동의 후 이전 알림 읽음·발송 임대 무효화, 새 알림/참석 확인. 공급자 전송 과거 증거·원래 사용 티켓 유지 |
| 채팅 | 열린 화면 3초 갱신, 복귀 즉시 확인. 수신 실패와 빈 대화 분리·재시도. 중복 클릭 전송 방지, 과거 메시지 읽을 때 자동 스크롤 강제 안 함. 최신 1,000개 표시 |
| 알림 열람 | 화면에 가져온 본인 알림 ID만 읽음 처리. 기존 일괄 읽기로 보지 못한 참석 안내까지 확인한 것으로 세지 않음 |
| 개인정보 | 운영 메모에 전화번호 복사 금지. 탈퇴 시 새 작업 메모·연락 동의/선택 이력 제거. 동의 철회 즉시 조회 차단 |

일정 변경은 운영자 대리 동의나 유료 재예약이 아니다. 웹 브라우저를 닫은 이용자에게
새 외부 알림을 보내는 기능은 이번에 추가하지 않았다. 앱 폴링은 푸시/카카오 발송이 아니다.

## 검증표

최종 실행 결과와 배포 증거는 검사 종료 후 아래에 기록한다. 대역·자동화·사람 확인을 분리한다.

| 검증 | 상태 |
| --- | --- |
| 타입/린트/빌드·대비·고정 AI/연령/신원 계약·DB·동시성 | 최종 재검증 중 |
| Chromium 남2/여4 전주기·운영 UI | 최종 재검증 중 |
| WebKit 남2/여4 전주기·운영 UI | 최종 재검증 중 |
| 양 엔진 기존 가입/무료·유료 대역/인터뷰/어드민 회귀 | 최종 재검증 중 |
| 실제 AI 새 소개장 | 1회 성공 9.64초, 후속 요청은 계정 일일 한도. 10회/만족도 미완료 |
| 실제 기기·실제 메일/SMS·MFA 소유/복구·48h 운영 관찰 | 미확인, 대표/실제 참가자 필요 |
| 카카오·실결제·통신사 본인확인 | 이번 범위 제외, 미개통/미검증 |

주문·티켓은 실제 DB 경로를 사용하되 PG는 테스트 대역이다. 실제 카드 승인/취소가 아니다.
테스트 계정/사진/약속만 생성·시간 이동·정리하며 기존 회원·운영 결제 플래그는 QA로 변경하지 않는다.

## UI 마감 근거

`emil-design-eng`의 상태/가독성 절제와 `mobile-native`의 터치·스크롤·작은 화면 기준을 적용했다.
독립 리뷰어 검증이나 실제 휴대전화 조작 완료를 주장하지 않는다.

| Before | After | Why |
| --- | --- | --- |
| 채팅 진입 때만 조회·최초 1,000개만 반환 | 보이는 화면 갱신·최신 1,000개·실패 재시도 | 응답을 놓치고 만남이 끊기는 문제 방지 |
| 새 메시지가 읽던 과거 위치를 밀어냄 | 위치 보존·최근 메시지로 이동 버튼 | 읽기와 답장 주도권 유지 |
| 모달 등장 중 글자 대비 저하·작은 영문 닫기 | 카드 opacity 전환 제거·44px 한국어 닫기 | 애니메이션 중 가독성·손가락 조작 |
| 운영 경고만 남고 검토 완료 구분 없음 | 독립 작업·완료 사유·새 경고 재개 | 한 사람이 같은 건을 반복 검토하지 않음 |
| 연락처를 인증 수집 목적과 혼용할 위험 | 선택 동의·미동의 가림·조회 기록 | 신뢰와 목적 제한 |
| 긴 대화의 키보드 스크롤 접근 불가 | 이름 있는 포커스 가능한 대화 영역 | 키보드·보조기술 접근 |
| 로그인 URL만 보고 다음 자동화 실행 | 홈 UI 도착까지 대기·앱의 중복 이동 방지 | WebKit의 주소 갱신과 화면 도착을 구분 |

## 대표가 순서대로 할 일

1. 본인 iPhone/Safari·Android/Chrome에서 가입→사진 3장→프로필 승인→대화 입력→뒤로/재진입을 각 1회. 회사 메일·SMS 실수신 확인. 실패하면 모집 보류.
2. 관리자 MFA와 복구수단을 직접 확인하고, 실제 연락 가능한 고객문의 주소/연락처를 열어 본다.
3. 약속 당일 확인 가능한 인원만 **무료 초대**. 제안은 총 20명 이내부터, 실제 매칭 가능한 존·성별 수급에 맞춰 분할 모집. 권고안이며 자동 모집/계정 생성/광고를 실행하지 않았다.
4. 첫 5–8명 소개글 작성에 동행: 사실 오류·나다움·길이·편안함 평가, 최종 승인 전 상대 비공개. AI 실패 시 직접 작성 가능 여부도 확인.
5. 매일 오전/오후 작업함의 신고·사진·문의·매칭 대기 확인. 약속 D-4h와 D-2h 연락 필요 작업 재확인. 동의한 회원만 전화, 나머지는 앱 문의. 확인 불가하면 사유 기록 후 취소·티켓 처리 확인.
6. 48시간 누락/경고/후기/운영 소요시간 관찰. 1인 운영 감당 여부, 성별 대기시간, 소개→수락→실제 만남 전환을 보고 모집 확대. 카카오/결제/본인확인은 별도 게이트 통과 후 활성화.

외부 알림이 없는 동안 “앱을 닫아도 자동으로 안내한다”, 공인 본인확인 이전에 “신원·성인을 보장한다”,
실제 만남 이전에 “만남을 보장한다”는 문구로 모집하지 않는다.

## 릴리스 증거

PR/커밋·CI·운영 배포 버전 확인 결과는 머지/배포 후 기록한다.

운영 설정 읽기 전용 확인(2026-10-17): `payments_enabled=false`, `identity_required=false`,
`admin_mfa_required=false`. 추가 요청 리마인드 자동화 규칙은 `off`였다.
대표의 MFA 등록/복구 확인 없이 강제 플래그를 켜 계정을 잠그지 않았다. 모집 전 확인이 필요한 조건이다.
