# 애프터 무료 초대 베타 마감 점검

2026-10-17. 범위: 현재 할 수 있는 제품/운영 코드와 회귀 검증. 카카오 발송·실결제·통신사 본인확인은 대표 요청으로 후속 분리. HANDOFF는 수정하지 않는다.

## 오픈 판단

**소규모 무료 초대 베타는 조건부 GO, 유료 공개 출시·대규모 광고는 NO-GO.**

대표가 **회사 메일·SMS 코드 수신, 실제 기기의 가입·사진·키보드 동작을 모두 확인했다**고 알려주었다. 자동화 결과와 별도로 사람 확인 완료로 기록한다. 기종/OS는 특정하지 않았으므로 iPhone·Android 양쪽 완료로 확대하지 않는다.
무료 초대 전 남은 핵심 조건은 **대표 운영 관리자 MFA/복구수단 확인**이다. AI 품질의 10회 실호출/사용자 만족도 평가도 미완료이므로
첫 5–8명은 인터뷰 동행/소개글 승인 관찰을 하고 확대 여부를 판단한다.
기술 점검 통과를 법률·PG 심사·실명/성인 확인 완료로 표현하지 않는다.

| 알림 열람 | 화면에 가져온 본인 알림 ID만 읽음 처리. 기존 일괄 읽기로 보지 못한 참석 안내까지 확인한 것으로 세지 않음 |
| 개인정보 | 운영 메모에 전화번호 복사 금지. 탈퇴 시 새 작업 메모·연락 동의/선택 이력 제거. 동의 철회 즉시 조회 차단 |
| 관리자 MFA | 운영 설정에서 인증앱 QR 등록→실제 코드 확인→복구수단 직접 확인 후 중요 조치 MFA 강제 켜기. 새 로그인 시 같은 화면에서 재인증. 배포 시 자동 강제 안 함 |

일정 변경은 운영자 대리 동의나 유료 재예약이 아니다. 웹 브라우저를 닫은 이용자에게
새 외부 알림을 보내는 기능은 이번에 추가하지 않았다. 앱 폴링은 푸시/카카오 발송이 아니다.

## UI 마감 근거

`emil-design-eng`의 상태/가독성 절제와 `mobile-native`의 터치·스크롤·작은 화면 기준을 적용했다.
독립 리뷰어 검증이나 실제 휴대전화 조작 완료를 주장하지 않는다.

| Before | After | Why |
| --- | --- | --- |
| 채팅 진입 때만 조회·최초 1,000개만 반환 | 보이는 화면 갱신·최신 1,000개·실패 재시도 | 응답을 놓치고 만남이 끊기는 문제 방지 |
| 새 메시지가 읽던 과거 위치를 밀어냄 | 위치 보존·최근 메시지로 이동 버튼 | 읽기와 답장 주도권 유지 |
| 모달 등장 중 글자 대비 저하·작은 영문 닫기 | 카드 opacity 전환 제거·44px 한국어 닫기 | 애니메이션 중 가독성·손가락 조작 |
| 운영 경고만 남고 검토 완료 구분 없음 | 독립 작업·완료 사유·새 경고 재개 | 한 사람이 같은 건을 반복 검토하지 않음 |
| 연락처를 인증 수집 목적과 혼용할 위험 | 선택 동의·미동의 가림·조회 기록 | 신뢰와 목적 제한 |
| 긴 대화의 키보드 스크롤 접근 불가 | 이름 있는 포커스 가능한 대화 영역 | 키보드·보조기술 접근 |

| MFA 검사는 있으나 등록·재인증 화면 없음 | 운영 설정에서 단계별 등록·본인 복구 확인 후 강제, 완료 시 입력칸 숨김 | SQL 없이 운영자 보안 설정, 인증 완료와 해야 할 일 구분 |

## 대표가 순서대로 할 일

1. **회사 메일·SMS 실수신과 기기의 가입/사진/키보드는 확인 완료**. 이어 첫 참가자의 iPhone/Safari·Android/Chrome에서 프로필 승인→대화→뒤로/재진입까지 관찰한다. 두 OS·백그라운드·안전영역 전체 검증을 완료로 세지는 않는다.
2. [운영 설정](https://aftersunset.kr/admin/settings)의 **관리자 보안**에서 인증앱 등록→6자리 코드 확인→안전한 백업/예비 인증앱 직접 확인→**중요 조치 MFA 필수로 켜기**. 새 로그인에서도 같은 화면에서 재인증해 본다. 실제 연락 가능한 고객문의 주소/연락처도 열어 본다. 이는 대표가 직접 할 일이며 합성 계정의 성공으로 대체하지 않는다.
3. 약속 당일 확인 가능한 인원만 **무료 초대**. 제안은 총 20명 이내부터, 실제 매칭 가능한 존·성별 수급에 맞춰 분할 모집. 권고안이며 자동 모집/계정 생성/광고를 실행하지 않았다. 초대코드/가입 총원 제한을 새로 구현한 뜻은 아니며, 사진 승인·큐레이션과 모집량을 운영자가 통제한다.
4. 첫 5–8명 소개글 작성에 동행: 사실 오류·나다움·길이·편안함 평가, 최종 승인 전 상대 비공개. AI 실패 시 직접 작성 가능 여부도 확인.
5. 매일 오전/오후 작업함의 신고·사진·문의·매칭 대기 확인. 약속 D-4h와 D-2h 연락 필요 작업 재확인. 동의한 회원만 전화, 나머지는 앱 문의. 확인 불가하면 사유 기록 후 취소·티켓 처리 확인.
6. 48시간 누락/경고/후기/운영 소요시간 관찰. 1인 운영 감당 여부, 성별 대기시간, 소개→수락→실제 만남 전환을 보고 모집 확대. 카카오/결제/본인확인은 별도 게이트 통과 후 활성화.

외부 알림이 없는 동안 “앱을 닫아도 자동으로 안내한다”, 공인 본인확인 이전에 “신원·성인을 보장한다”,
실제 만남 이전에 “만남을 보장한다”는 문구로 모집하지 않는다.

## 릴리스 증거

릴리스 [PR #114](https://github.com/c-yeonwoo/after/pull/114), [해당 PR 검사](https://github.com/c-yeonwoo/after/pull/114/checks), [main 릴리스 기록](https://github.com/c-yeonwoo/after/actions/workflows/release.yml). 머지 전 CI 통과와 main의 DB→Edge→프론트→배포 커밋 검증 성공을 배포 완료 기준으로 둔다. 최종 운영 버전·실행 링크는 PR 최종 검증 댓글과 인계 메시지에 기록한다.

운영 설정 읽기 전용 확인(2026-10-17): `payments_enabled=false`, `identity_required=false`,
`admin_mfa_required=false`. 추가 요청 리마인드 자동화 규칙은 `off`였다.
대표의 MFA 등록/복구 확인 없이 강제 플래그를 켜 계정을 잠그지 않았다. 모집 전 확인이 필요한 조건이다.

### 관리자 인증앱 유의사항

- QR/설정키는 본인 기기의 인증앱에만 등록하고 채팅·운영 메모·스크린샷 공유에 남기지 않는다. 이 화면은 별도의 복구코드를 발급하지 않는다. 인증앱의 안전한 개인 백업이나 예비 기기를 준비하고 유일한 인증앱을 삭제하지 않는다.
- 예비 인증앱 추가는 현재 세션 2단계 인증 후 가능하다. 등록 중 취소는 해당 미완료 등록만 정리한다. 중요 조치 강제 해제도 인증된 관리자 세션을 요구한다.
- 공급자 설정에서 TOTP 등록/확인이 꺼진 경우 별도 안내가 나온다. 프로젝트 소유자가 Supabase Auth 설정을 확인한다. 로컬/CI는 TOTP를 켰으며, 다른 인증·결제 설정을 운영에 일괄 덮어쓰지 않는다.
- MFA 앱 분실 시 일반 비밀번호만으로 강제를 끄는 우회로를 제공하지 않는다. 프로젝트 소유자가 본인 확인 후 Supabase 관리 기능으로 복구하고 감사 기록을 남긴다.
- 구현 기준: [Supabase TOTP 공식 절차](https://supabase.com/docs/guides/auth/auth-mfa/totp), [코드 검증 API](https://supabase.com/docs/reference/javascript/auth-mfa-challengeandverify). 등록·코드 검증·세션 강화·서비스 강제 설정을 분리했다.
