# 애프터 소개 프로필 인터뷰 재설계

작성일: 2026-10-16. 검토 기준: `main`의 `5c447d4`. 범위: 가입 중 인터뷰, 소개글 생성·수정·확정, 기존 회원의 재작성, 운영 품질 관측.

2026-10-17 후속 설계: [프로필 엔진과 인터뷰형 소개장 v3](./ai-profile-engine-v3-design.md). 실제 생성 오류 진단, 생활 정보 선행, 선택형 입력, 내용 이해 확인, 질문별 소개장으로 개편하는 **구현 전 설계안**이다. 아래 문서는 현재 v2 구현의 기준과 이력을 보존한다.

**구현 기준 문서.** 사용자가 확정한 방향은 **핵심 질문 3개와 선택 추가 질문 최대 2개로 끝이 보이는 인터뷰**다. 핵심 흐름을 제품 코드에 적용했고, DB 권한·저장/재개·최종 공개·브라우저 흐름을 자동 검증했다. 아래의 ‘현재 경험’ 진단은 개편 전 상태를 기록한 것이며, 문장별 근거 연결 등 일부 권고와 실제 회원 만족도·모델 출력 품질은 베타 관찰로 더 검증해야 한다. 기존 통합 설계와 HANDOFF를 덮어쓰지 않는다.

핵심은 글을 그럴듯하게 대신 쓰는 것이 아니다. **회원이 부담 없이 자기 이야기를 꺼내고, 상대가 실제로 대화를 시작할 단서를 얻도록 돕는 것**이다. 평범한 일상도 충분한 재료이며, 표현력·취미 개수·자기 홍보 능력을 가입 자격처럼 평가하지 않는다.

정적 코드 확인에 근거한다. 이 문서 작성 중 실제 회원 인터뷰나 실제 모델 호출은 하지 않았다.

추가 회귀 후보: 생성 effect는 `profile` 변경 시 이전 요청을 취소 표시하지만 같은 payload는 ref로 재호출을 막는다. 생성 도중 제목 수정 등으로 `profile`이 바뀌면 응답 반영과 로딩 해제가 누락될 가능성이 있다. **정적 위험 분석이며 재현 완료 버그로 표시하지 않는다.** 새 설계에서 요청 상태를 분리하고 반드시 회귀 테스트한다.

## 3. 경험의 성공 기준

회원은 “멋있게 써야 한다”가 아니라 “이 정도면 나를 설명할 수 있겠다”고 느껴야 한다. 읽는 사람은 같은 직장인이라는 조건 외에 **어떤 일상을 보내는지, 처음 어떻게 말을 걸면 좋을지**를 알 수 있어야 한다.

- 첫 5초: 해야 할 일과 끝이 보인다. 분석·궁합·성격 진단을 내세우지 않는다.
- 작성하는 몇 분: 답이 짧거나 취미가 없어도 진행할 수 있다. 질문을 바꾸거나 건너뛸 수 있다.
- 마지막 확인: 내 말과 아닌 말을 구별하고 쉽게 고칠 수 있다. 승인 전에 공개되지 않는다.
- 가입 이후: 홈에서 다시 취향 문답을 숙제로 내지 않는다. 재작성은 내 프로필에서 선택한다.
- 장기 사용: 같은 문체의 사람이 늘어나지 않는다. AI 이용 여부나 글의 세련됨으로 회원을 등급화하지 않는다.

완료 시간 3–5분은 **검증할 가설**이다. 아직 사용자에게 소요시간을 약속하지 않는다.

## 4. 권고 흐름과 화면 계층

```text
기존 인증·기본 정보
  → 소개글 시작 안내
  → 핵심 이야기 1 / 3: 요즘의 일상
  → 핵심 이야기 2 / 3: 편해지는 방식
  → 핵심 이야기 3 / 3: 대화의 시작점
  → 답변 검토 [필요하면 선택 추가 질문 0–2개]
  → 공개할 내용 확인
  → 소개글 만들기
  → 실제 소개 화면으로 읽고 수정
  → 이 소개글로 저장
  → 나머지 가입 요건 판정 → 준비 완료 / 필요한 요건 안내

시작 안내 → 직접 쓰기 → 공개할 내용 확인·미리보기 → 동일한 저장 절차
중단 → 저장된 위치에서 계속
기존 회원 → 내 프로필에서 재작성 → 기존 공개본 유지 → 확인 후 교체
```

가입 전체는 `인증 / 기본 정보 / 소개글 / 완료`의 큰 단계로 표시하고, 소개글 안에서는 `이야기 / 공개할 내용 / 미리보기`로 방향을 알려준다. 큰 진행률과 작은 진행률 막대를 겹쳐 쓰지 않는다. 핵심 질문만 `1/3`처럼 표시하며 추가 질문은 `조금 더 알려주기 · 선택`으로 표시한다. 질문이 늘었다고 진행률을 뒤로 돌리지 않는다.

한 화면에서 가장 먼저 보일 것은 **질문, 입력 영역, 다음 행동**이다. 예시·설명·저장 상태는 보조 계층으로 둔다.

```text
뒤로                    소개글 · 이야기           나가기

이야기 1 / 3
요즘 퇴근 후나 쉬는 날,
어떻게 시간을 보내세요?

특별한 취미가 없어도 괜찮아요.

내 이야기
┌─────────────────────────────┐
│ 집에서 밥 먹고 드라마 봐요.  │
│                             │
└─────────────────────────────┘
예시 보기              다른 질문으로 답하기

저장됨
[ 다음 이야기 ]
나중에 답하기
```

## 5. 화면별 질문과 문구

### S0 소개글 시작

- 제목: **“어떤 사람인지, 조금만 들려주세요.”**
- 설명: “짧게 답하면 소개글 초안을 정리해드려요. 마지막에 직접 고칠 수 있어요.”
- 범위: “질문 3개 · 필요한 경우 추가 질문 최대 2개”
- 주 행동: **“이야기 시작하기”**. 보조 행동: “직접 소개글 쓰기”.
- AI 사용 고지: “AI가 답변을 정리해요. 확인한 소개글만 상대에게 보여요.” 처리 범위·위탁 정보는 실제 정책 링크로 제공하며 필요한 동의 절차와 일치시킨다.
- 질문 선택에도 AI가 답변을 처리한다는 점을 상세 안내에 명시한다. `상대에게 공개하지 않음`과 `외부 AI에 전송하지 않음`을 혼동하게 하지 않는다. 직접 쓰기 경로는 AI 호출 없이 동일하게 저장 가능하도록 한다.
- 챗봇 캐릭터·사람처럼 보이는 운영자 이름·분석 점수·가짜 타이핑을 넣지 않는다.

### S1 요즘의 일상

질문: **“요즘 퇴근 후나 쉬는 날, 어떻게 시간을 보내세요?”**

상시 설명은 “특별한 취미가 없어도 괜찮아요.” 한 줄만 둔다. placeholder는 “편하게 적어주세요.”로 짧게 둔다. 완성된 모범 답안을 입력창에 깔지 않는다.

예시를 펼치면 평범한 길이로 보여준다. 예시 클릭이 실제 답변을 자동 입력하거나 제출하지 않는다.

- “집에서 밥 먹고 드라마 봐요.”
- “시간이 나면 동네를 걸어요.”
- “요즘은 일이 바빠서 쉬는 게 제일 좋아요.”

대체 질문: “최근에 쉬면서 좋았던 순간이 있었나요?” 질문만 바꾸고 이미 쓴 답은 보존한다. 직업을 보고 야근·소득·생활 패턴을 추측하지 않는다.

### S2 편해지는 방식

질문: **“처음 만난 사람과는 어떻게 가까워지는 편인가요?”**

설명: “말이 많아도, 천천히 친해져도 괜찮아요.”

- “처음에는 듣다가 익숙해지면 말이 많아져요.”
- “같이 걷거나 뭘 하면서 얘기하면 편해요.”
- “저도 잘 모르겠어요.”도 허용하며 다른 질문이나 건너뛰기를 제공한다.

대체 질문: “첫 만남은 어떤 분위기면 편할까요?” 상대에게 요구하는 조건만 수집하지 않고, 나를 만났을 때의 경험을 설명하도록 돕는다. 내향·외향, 애착 유형 등의 진단 라벨은 붙이지 않는다.

### S3 대화의 시작점

질문: **“처음 만나면 어떤 이야기를 나눠보고 싶어요?”**

설명: “요즘 관심 가는 것이나 가볍게 나눌 이야기면 돼요.”

- “요즘 보는 드라마요.”
- “퇴근하고 뭐 먹는지 궁금해요.”
- “서로 주말을 어떻게 보내는지요.”

대체 질문: “요즘 자주 보거나 듣거나 찾아보는 게 있나요?” S1에서 이미 충분히 답했다면 “앞에서 적은 이야기로 할게요”를 제공하고 해당 답변을 참조한다. 같은 말을 두 번 쓰게 하지 않는다.

### 공통 입력 규칙

- 필수 최소 글자 수와 채점처럼 보이는 카운터를 없앤다. 입력 상한은 답변당 300자; 남은 글자가 50자 이하일 때만 안내한다.
- 공백만 있으면 조용히 다음으로 넘기지 않고 “나중에 답하기”를 선택할 수 있게 한다. 건너뜀은 저장하되 내용을 추정하지 않는다.
- 인터뷰의 세 질문은 모두 응답 또는 건너뜀 상태를 가져야 종료되지만, 모든 답변이 필수는 아니다.
- 세 질문을 모두 건너뛴 경우에는 초안을 지어내지 않는다. “소개글에 담을 이야기가 아직 없어요”와 “하나만 답하기 / 직접 쓰기 / 저장하고 나가기”를 제공한다.
- 최소 한 개의 공개 가능한 자기 설명이 있으면 짧은 소개글을 허용하는 방향을 권고한다. 인사말·무의미 문자열만 있는 상태와 짧지만 정보가 있는 상태를 구별한다. 모델의 품질 점수만으로 가입을 거절하지 않는다.
- 한글 IME 조합 중 Enter는 제출하지 않는다. Enter는 줄바꿈, 다음 이동은 버튼으로만 한다.

### S4 필요한 경우에만 추가 질문

핵심 질문을 다 받은 뒤 한 번 분석한다. 매 답변마다 칭찬·요약·LLM 요청을 끼워 넣지 않는다. 이미 답한 내용·건너뛴 민감한 내용은 다시 묻지 않는다.

| 원래 답변              | 되물을 수 있는 질문                   | 묻지 않아야 하는 내용          |
| ---------------------- | ------------------------------------- | ------------------------------ |
| “산책이요”             | “산책할 때 어떤 점이 좋아요?”         | 자주 가는 정확한 위치·시간     |
| “처음엔 조용해요”      | “어떤 이야기가 나오면 조금 편해져요?” | 내향형인지, 관계 문제가 있는지 |
| “집에서 드라마 봐요”   | “최근에 기억에 남은 드라마가 있나요?” | 집 주소, 같이 사는 사람        |
| “요즘은 쉬기만 해요”   | 필요 없으면 추가 질문 없음            | 취미를 억지로 찾게 하기        |
| 이미 구체적인 답변 3개 | 추가 질문 없음                        | 분량을 채우기 위한 추가 질문   |

- 최대 2개, 같은 주제에는 최대 1개. 둘을 한 번에 쏟지 않고 하나씩 표시한다.
- 질문 앞에 회원이 쓴 문장을 짧게 인용한다. 근거 없는 “차분한 분이시군요”는 금지한다.
- 매번 **“이 정도로 소개글 만들기”**를 제공한다. 추가 질문을 건너뛰어도 불이익이 없다.
- 분석 실패·지연 시에는 이 단계를 생략한다. 기본 인터뷰만으로 직접 쓰기와 원문 정리가 가능해야 한다.
- 우선순위는 대화 단서 부족 → 모호한 자기 설명. 정보가 충분하면 0개를 반환하는 것이 정상 성공이다.
- 위 질문은 운영 승인을 거칠 질문 은행의 후보 예시다. 구현 시 모델은 승인된 질문 ID와 인용할 근거를 고르고, 임의로 민감한 질문을 생성하지 않는다.

### S5 공개할 내용 확인

제목: **“이 이야기를 소개글에 담을게요.”**

답변을 읽기 쉬운 짧은 항목으로 보여주고 각 항목에 `담기 / 빼기 / 수정`을 제공한다. 기본 선택은 현재 인터뷰에서 작성한 비민감 내용이되, 다음 행동 전 선택 상태를 보여준다. 자동 감지된 연락처·상세 위치·제3자 정보는 제외 후보로 표시하고 일반화 또는 삭제를 안내한다. 자동 탐지가 모든 개인정보를 찾는다고 안내하지 않는다.

관심사·대화 주제 태그가 필요하면 최대 3개만 **제안**한다. `확인한 태그`만 저장하며 안 골라도 진행한다. “차분함·성실함”처럼 행동에서 성격을 추정한 태그는 제안하지 않는다. 상대 취향 태그가 실제 큐레이션에 필요한 경우 별도 비공개 선택 정보로 다루며 추론해 채우지 않는다.

주 행동: **“이 내용으로 소개글 만들기”**. 선택한 공개 재료만 생성 요청에 보낸다. 상세 근무지·정확한 시간대·일정 가용성은 이 소개글 기능에서 새로 수집하지 않는다.

### S6 소개글 생성과 미리보기

- 생성 중: “적어주신 이야기를 소개글로 정리하고 있어요.” 기존 답변은 열람할 수 있다. 가짜 퍼센트·단계별 성격 분석 표시를 하지 않는다.
- 초기에는 제목 1개와 소개글 1개만 만든다. “다른 제목 보기”를 누를 때만 최대 2개 대안을 요청한다.
- 권고 길이: 소개글 2–4문장, 보통 80–220자. 재료가 짧으면 더 짧아도 허용한다. 상한 300자는 유지하되 **최소 100자 강제는 제거**한다.
- 제목은 꾸민 카피 대신 내용을 짚는 한 문장으로 한다. 최소 12자 강제를 제거하고 상한 35자를 유지한다. 제목을 쓰지 않는 대안은 스키마·수신 화면 영향 검토 전 별도 미결정으로 둔다.
- 제목 **“이렇게 소개할까요?”** 아래 실제 `ProfileDetail`·`toProfileView` 경로를 재사용한다. 승인 예정 스냅샷을 넘기며 옛 답변을 따로 섞지 않는다.
- 기본 화면은 읽는 화면이다. “소개글 수정”을 누르면 편집 모드로 바뀐다. 편집하지 않을 때 9행 textarea를 계속 노출하지 않는다.
- 보조 행동: “더 짧게 / 내 표현 살리기 / 답변 수정”. AI가 다시 쓴 글은 비교 후 **“바꾼 글 사용”**을 눌러야 적용된다.
- 원문 근거는 “어떤 답변으로 썼나요?” 아래 문장별로 펼친다. 인용 원문은 본인에게만 보여준다.
- 주요 행동: **“이 소개글로 저장”**. 옆 설명: “저장한 소개글이 상대에게 보여요.” 인증·검수 완료 전 실제 노출 여부는 기존 서버 자격을 따른다.
- 생성 결과가 마음에 안 들면 원문 기반 소개글이나 직접 작성으로 완료할 수 있다. AI 사용 자체는 필수가 아니다.

### S7 저장과 기존 회원 수정

저장 완료와 소개 가능 상태는 구별한다. 사진 검수 등이 남아 있으면 “소개글을 저장했어요” 다음에 실제 남은 항목만 보여준다. 모든 조건이 완료되면 홈은 소개 대기 상태로 이어지며 인터뷰를 다시 요구하지 않는다.

기존 회원이 편집을 시작해도 기존 공개 소개글은 유지한다. 새 초안의 저장과 공개본 교체는 다른 명령이다. 사용자가 최종 저장하기 전에는 상대나 운영자 일반 화면에 생성 중인 글이 노출되지 않는다. 단, 기존 공개본에서 안전 문제가 발견된 경우 기존 안전 정책에 따른 제한은 별도로 적용한다.

## 6. 완성 예시와 문체 계약

아래는 실제 회원이 아닌 합성 예시다.

**입력**

- “퇴근하면 집에서 밥 먹고 드라마 봐요. 요즘은 자극적인 것보다 웃긴 게 좋아요.”
- “처음엔 듣는 편인데 익숙해지면 말이 많아져요.”
- “서로 자주 먹는 저녁 메뉴 얘기요.”

**제목**: “요즘은 웃긴 드라마가 좋아요”

**소개글**: “퇴근하면 집에서 밥 먹고 드라마를 봐요. 요즘은 자극적인 것보다 웃긴 게 좋더라고요. 처음에는 듣는 편인데 익숙해지면 말이 많아져요. 만나면 서로 자주 먹는 저녁 메뉴 이야기도 나눠보고 싶어요.”

**금지되는 변형**: “소소한 행복을 아는 따뜻하고 다정한 사람입니다. 맛집 탐방과 영화 감상을 즐기며 깊이 있는 관계를 꿈꿉니다.” 원문에 없는 성격·취미·관계관을 추가했기 때문이다.

얇은 입력 “쉬는 날엔 집에서 쉬어요”는 “쉬는 날에는 집에서 쉬는 편이에요” 정도로 남길 수 있다. 이를 미완성 점수로 깎거나 100자를 채우려고 다른 특성을 붙이지 않는다. 품질 향상은 선택 질문으로 돕는다.

문체 규칙: 존댓말 유지, 본인의 특징적 단어 보존, 맞춤법·중복만 절제해서 수정, 긍정/부정/가끔/요즘/희망의 범위 유지. “해보고 싶어요”를 “즐겨요”로 바꾸지 않는다. 수식어·대구·상투적인 마지막 한 문장을 일률적으로 붙이지 않는다. 물음표·느낌표 자체를 사실성 위반으로 취급하지 않고 사람의 표현과 생성 스타일을 분리한다.

## 8. AI 역할과 데이터 계약 권고

### 분리할 책임

1. **질문 선택기**: 세 답변의 구체성·중복을 보고 승인된 질문 ID 0–2개와 근거 구절을 반환한다. 성격 분석이나 궁합 추정은 하지 않는다.
2. **문장 편집기**: 회원이 공개 대상으로 선택한 사실만으로 초안을 쓴다. 각 문장·제목에 원본 답변 ID와 근거 범위를 붙인다.
3. **검증기**: 구조·소유자·버전·금지 노출·근거 범위·문장별 지원을 확인한다. 단순 인용 포함 검사만으로 모든 문장이 사실이라고 결론 내리지 않는다.
4. **회원**: 최종 공개 내용을 결정한다. 회원 승인도 실제 직업·취미의 객관적 사실 인증과는 다르다.

정상 경로는 분석 1회 + 생성 1회를 목표로 한다. 추가 질문을 받는 매 순간 새 대화를 호출하지 않는다. 후속 답변을 받은 뒤 최종 생성에서 함께 반영한다. 이미 충분한 경우에도 분석 결과 0개는 캐시한다.

질문 선택용 요청에서도 연락처·상세 위치 등 불필요한 정보를 먼저 제거하고 필요한 답변만 보낸다. AI 미사용을 선택한 경우 정적 핵심 질문과 직접 작성만으로 마친다. 이후 공개 대상에서 제외한 답변은 초안 생성 요청에는 보내지 않지만, 앞서 질문 선택에 사용한 전송 사실까지 없어진 것으로 표시하지 않는다.

### 권고 저장 모델

| 데이터             | 최소 필드/책임                                                                                                   | 노출                        |
| ------------------ | ---------------------------------------------------------------------------------------------------------------- | --------------------------- |
| interview draft    | owner, schema_version, revision, stage, questions/answers/skips, included_answer_ids, confirmed_tags, updated_at | 본인; 예외 지원 접근만 감사 |
| generated revision | draft_revision, source_hash, prompt/model_version, candidate text, sentence evidence, status                     | 본인만, 미승인              |
| published profile  | approved text, confirmed tags, published_revision, approved_at, origin                                           | 기존 소개 자격·권한 범위    |
| ai run             | feature, result/error code, latency, usage, request_id                                                           | 운영 집계; 원문·생성문 없음 |

`source_hash`에는 공개 선택 내용·질문 버전·문체 옵션·프롬프트 버전을 포함한다. 캐시는 회원별로 격리하고 모델 버전도 키에 포함한다. 해시는 익명화가 아니므로 공개 로그에 내보내지 않는다.

자동 저장은 입력 후 약 800ms 및 blur/다음 이동 시 시도하고, `revision` 기반 조건부 갱신을 사용한다. 최종 저장은 서버 트랜잭션으로 **소유자·현재 revision·승인한 candidate·확인한 공개 내용**을 대조한다. 편집 중 원문이 바뀌면 후보는 stale이다. 낡은 후보를 그대로 publish하지 않는다.

수동 편집본은 생성본과 별도 버전으로 보존한다. 사용자가 직접 추가한 문장은 `member_authored`로 표기하고 모델 근거가 있는 것처럼 꾸미지 않는다. 개인정보·안전 검사와 최종 미리보기는 직접 작성에도 동일하게 적용한다.

### 오류·비용·안전

- API는 `timeout / rate_limited / unavailable / invalid_output / unsafe_content / source_changed / conflict` 등을 구분한다. 화면에서는 기술 용어 대신 행동 가능한 문구로 변환한다.
- 같은 요청 재시도는 같은 request ID로 멱등 처리한다. 초안 수정으로 새 요청이 되면 revision과 source hash가 달라진다.
- 기존 프로필 5회/일 제한을 분석+생성으로 그대로 공유하면 가입 중 조기 소진될 수 있다. 분석·작성·수정별 예산과 계정 단위 총상한을 함께 설계한다. 구체 상한은 합성·사용자 표본의 비용을 측정한 뒤 정한다.
- 모델 선택은 이름이나 추정 비용이 아니라 동일 입력의 사실 충실도·말투 보존·지연·실제 토큰 비용으로 결정한다. 이 설계에서 제공자/모델 교체는 하지 않는다.
- 입력은 지시문이 아닌 자료로 격리한다. 질문 은행 밖 질문, 외부 링크, 연락처, JSON 밖 텍스트, 근거 없는 숫자·직업·일정은 거부하거나 회원이 직접 수정하게 한다.
- 질문·초안의 원문을 analytics, 에러 로그, 알림, 텔레그램 등에 보내지 않는다. 운영자의 일반 목록에서도 숨긴다.
- 계정 탈퇴·삭제 시 원문, 후보, 캐시, 근거 사본과 비동기 작업을 함께 처리한다. 삭제된 계정의 늦은 AI 응답은 저장하지 않는다. 보관기간·예외 지원 권한은 개인정보 정책 확인 전 미확정이다.

## 9. 기존 제품과의 연결

- `profile.ts`의 질문 정의와 `signup.tsx`의 거대 분기를 작은 단계 컴포넌트·명시적인 상태로 나눈다. 이 설계를 이유로 앱 전체 폼 프레임워크를 갈아엎지 않는다.
- `ProfileDetail`과 `toProfileView`는 미리보기·내 프로필·소개 상세의 공통 렌더 경로로 재사용한다. 읽기 권한은 별도로 유지한다.
- `interests/topics/match_tags/details`의 소비처를 먼저 목록화한다. 태그 선택을 선택사항으로 바꾸기 전에 큐레이션·운영 목록·기존 Q&A 표시가 빈 배열에서도 동작하도록 한다. 빈 값을 성향 없음/부적합으로 취급하지 않는다.
- 기존 회원의 공개 글·태그는 보존한다. v1 답변을 v2 질문에 억지로 매핑하거나 성격 질문을 새 답변처럼 보이지 않는다. 기존 원문은 legacy source로 표시한다.
- 새 가입자 완료 요건에 공개 소개글 확정을 추가하되, 기존 `onboarding_step=7` 회원을 대량 미완료로 되돌리지 않는다. 기존 회원은 현재 글을 legacy published snapshot으로 이관한다.
- 새 재작성 초안의 미완료가 기존 회원의 소개 대기를 중단시키면 안 된다. 진행 중 약속·티켓·확정된 상대 관계도 건드리지 않는다.
- 직장·성인 인증의 확인 범위와 회원 자기소개는 분리한다. “검증된 소개글” 대신 “본인이 확인한 소개글”을 사용한다.

## 10. 화면 디자인과 접근성

최상위 `DESIGN.md`는 없다. 구현 기준은 최신 `src/styles.css`, [리브랜딩 설계](./after-rebrand-plan.md), 현재 공통 컴포넌트다. 과거 리브랜딩 문서의 HEX를 복사해 최근 이브닝 팔레트를 되돌리지 않는다.

- OPERATE형 작성 화면: 기존 `background/foreground/muted-foreground/primary/ring` 토큰 사용. 넓은 중립 면과 글이 중심이며 질문마다 색상 카드를 쌓지 않는다.
- Pretendard 유지. 질문 24–28px/1.4, 입력·본문·행동·핵심 안내 16px/1.6. 한 줄 소개의 기존 명조만 미리보기에서 유지한다.
- 좌우 20px, 본문 최대 480px, 제목→설명 8px, 설명→입력 24px, 입력→보조 행동 12px. 입력은 4행에서 시작해 최대 8행까지 늘린다.
- 주요 버튼 높이 52px, 보조 행동 터치 영역 최소 44px. 색상 외 밑줄·아이콘·문구로 상태를 구분한다. 확인되지 않은 개인정보 경고는 경고색만 칠하지 않는다.
- 360/390px: 한 열, 하단 행동과 입력이 키보드에 가려지지 않음. 키보드가 열리면 긴 안내는 접고 입력·다음 버튼은 스크롤로 도달 가능하게 한다.
- 768/1440px: 중앙 편집 열 유지. 공간이 남는다고 옆에 설명 카드·실시간 미리보기를 추가하지 않는다.
- 200% 확대·320 CSS px에서 가로 스크롤 없이 사용. 다크 모드의 입력·선택·오류·focus 대비도 검사한다.
- 질문 변경 시 제목으로 포커스 이동, 입력값 복원. 입력 도중 자동 단계 이동 금지. 저장 상태는 `aria-live=polite`로 과도하게 반복하지 않고, 오류는 입력과 `aria-describedby`로 연결한다.
- visible label 유지. 예시 펼침은 `aria-expanded`; 태그 제안은 checkbox. 삭제·건너뛰기·비공개 선택에 키보드 접근을 제공한다.
- 모션은 전환 150–200ms 정도만 쓰고 reduced-motion에서는 제거한다. 읽는 내용이 애니메이션 완료를 기다리게 하지 않는다.

## 12. 1인 운영 모니터링

운영 홈에는 새 AI 대시보드 카드를 여러 개 늘리지 않는다. 시스템 건강에서 **인터뷰 완료 흐름·AI 실패·회원 수정 부담**을 묶어 보고 예외에만 작업을 만든다.

- 단계별 수: 시작 → 핵심 질문 종료 → 공개 내용 확인 → 생성 시도 → 미리보기 → 저장. 직접 작성/AI를 분리하고 날짜·버전·대상 기수를 명시한다.
- 중단율은 단계 시작자를 분모로, 완료율은 고정된 기수의 시작자를 분모로 한다. 아직 작성 중인 사람을 최종 실패로 세지 않는다.
- 활성 작성 시간은 백그라운드·장기 이탈 시간을 제외한다. p50/p90과 표본수를 함께 표시한다.
- 추가 질문 0/1/2개, 건너뜀·대체 질문·원문으로 계속 비율을 본다. 추가 질문 수가 많다는 이유로 성과로 평가하지 않는다.
- “내 이야기처럼 느껴져요?” 선택형 피드백과 수정 이유(내용이 다름/말투가 어색함/너무 김)를 선택적으로 수집한다. 피드백을 쓰지 않아도 가입 가능하다.
- 알림은 원문 노출 의심·권한 문제 즉시, 동일 버전 오류 급증은 표본수와 함께 경보. 한 명의 짧은 답변을 운영자 호출 대상으로 만들지 않는다.
- 원문 열람은 회원 요청 등 명시적 목적이 있는 예외 지원에 한정하고 감사 기록을 남긴다. 운영자가 회원 승인 없이 소개글을 몰래 고치지 않는다.

핵심 품질 지표는 생성 성공률이 아니라 **근거 없는 문장 비율, 나다움 평가, 상대가 떠올린 대화 단서**다. 만남 성사율은 수급·사진·권역·일정의 영향도 크므로 인터뷰 효과로 단독 귀속하지 않는다.

## 13. 검증과 출시 기준

### 자동 검증

- 상태 전이: 모든 질문 건너뜀, 아주 짧은 답, 대체 질문, 추가 질문0/1/2, 중간 이탈·재개, 직접 쓰기.
- race: 생성 중 제목 수정, 답변 변경 후 옛 응답 도착, 뒤로갔다 재진입, 이중 탭 저장, 중복 요청, 저장 성공 후 응답 유실.
- 보안: 다른 회원 초안 조회/쓰기, 미승인 공개, 탈퇴 후 응답·캐시, 운영자 원문 최소권한, 인젝션과 연락처.
- 정합성: legacy 회원, 빈 태그, 새 가입 미확정, 공개본 유지, 최종 확정만 반영, 홈 재숙제 없음.
- 접근성: 모든 상태 키보드 조작, 오류 낭독, IME, 확대·다크·모바일 키보드·버튼 도달성.

### 실제 모델 평가

합성 입력 최소 60개로 충분한 답/한 단어/무취미/중복/모순/오타/영문 혼합/PII/제3자 정보/지시문 공격을 포함한다. 검증기 테스트와 별도로 **실제 설정된 모델의 출력**을 저장된 안전한 평가셋에서 평가한다. 공급자 비용은 실측한다.

문장별 사실 추가, 의도→사실 변환, 말투 보존, 질문 반복, 민감정보 재질문을 사람 검토로 채점한다. 합성셋에서 허위 사실·공개 제외 정보 유출·무권한 노출 1건이라도 발견하면 차단 원인을 고치고 재평가한다. 0건도 미래 무오류 보장은 아니다.

### 실제 사용자 과업

타깃 직장인 5–8명: 글쓰기 자신 없음, 취미 적음, 짧게 답함, 긴 답변, 이전 앱 피로 사용자 포함. 성별 모두 관찰하되 성별에 따라 질문 수준을 다르게 하지 않는다. 개인정보·연애사를 시험용으로 강요하지 않는다.

1. 설명 없이 소개글을 완성하게 한다. 시간과 멈춘 지점·도움 요청을 기록한다.
2. “상대에게 무엇이 보이나요?”를 묻고 실제 화면과 비교한다.
3. “나와 다른 부분 하나를 고쳐주세요” 과업으로 편집·승인을 확인한다.
4. 중간에 나갔다 돌아오게 하고 저장 상태 인지를 확인한다.
5. 합성 상대 프로필을 읽고 “처음 무슨 말을 걸고 싶은가요?”를 묻는다.

통과 조건: 치명적 원문/공개 범위 오해·내용 유실 0건, 참가자 전원 수정·저장 과업 수행 가능. 완료시간·나다움은 소표본 경향으로 보고, 숫자를 통계적 개선율로 홍보하지 않는다.

### 롤아웃

additive DB → 구버전 호환 API → 내부 테스트 플래그 → 허가된 소규모 베타 순서. 롤백은 신규 진입을 끄되 기존 v2 초안을 계속 조회/직접 작성/저장할 수 있게 한다. 단순 플래그 OFF로 v2 작성자를 v1 질문으로 몰거나 초안을 버리지 않는다. 공개본·약속·티켓은 보존한다.

**재사용:** StepShell의 기본 레이아웃·안전 영역, 기존 입력/버튼, ProfileDetail/toProfileView, 서버 소개 자격·검수, ai_runs의 예약·상태 원장, 기존 작업함·시스템 건강, 정책·탈퇴 처리. 재사용은 현재 코드가 새 계약을 모두 충족한다는 뜻이 아니다.
