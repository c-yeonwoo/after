# 내 비서 1차 릴리스 · 구현 및 검증

## 이번에 제공하는 경험

- 계정 확인과 프로필 준비를 분리한다. 인증 직후 바로 시작하거나 내 비서 홈에서 나중에 이어간다. 서버의 성인·프로필·사진 검수·소개 자격은 바꾸지 않는다.
- 내 비서 홈은 실제 소개/약속 상태와 다음 행동을 보여준다. 짧은 입력은 상태·프로필·가능 시간·대화 준비·고객센터로 안내한다. 이 안내는 로컬 의도 분류이며 자유 상담 LLM이 아니다.
- 열람이 허용된 상대의 공개 문장으로 첫 질문, 근거 인용, 이어갈 이야기를 준비한다. 요청할 때만 동의 후 AI를 호출한다. 상대에게 보내지 않으며 약속을 변경하지 않는다.
- 비서 발화는 라일락, 행동은 코럴, 선택은 플럼으로 구별한다. Wanted Sans와 비서 마크·발화면·질문/답변 패턴은 `DESIGN.md` 및 `.impeccable/design.json`에 자산화한다.

## 안전·비용 경계

`prepare-conversation`은 로그인과 본인 활성/완료 상태를 검사하고, 호출자 권한의 `get_public_profile`로 상대 열람을 확인한다. 모델 입력은 허용된 공개 문장뿐이다. 정확한 인용 검사와 별도 모델 검증을 통과해야 결과를 표시한다.

모델 선택은 `CONVERSATION_PREP_MODEL → PAIR_EDITOR_MODEL → DEFAULT_TEXT_MODEL` 순서다. 자동 재시도 없이 생성 1회와 검증 1회이며, 사용자별 24시간 신규 준비 5회로 제한한다. 같은 원문·모델·프롬프트 결과는 12시간 재사용한다. 서버 시간당 청소로 물리 보관은 최대 13시간이다.

공개 원문 변경·탈퇴 시 캐시를 지운다. 두 프로필의 revision 확인과 저장을 행 잠금 안에서 수행하므로, 진행 중 생성이 수정 전 인용을 다시 저장할 수 없다. 화면은 계정·상대·원문별 결과를 분리하고 권한 재조회 실패 시 기존 결과를 숨긴다.

자동 약속 확정·취소, 결제·환불, 상대 메시지 발송, 장기 개인 기억, 음성 비서, 심리 상담은 이번 구현에 포함하지 않는다.

실제 생성 예시(합성 프로필): “수영을 배우고 나면 그날 몸이나 기분이 좀 달라지나요?” 원문: “최근에는 수영을 배우기 시작했어요.” 실제 검증 모델은 `claude-sonnet-5-5`였으며 이 한 사례가 모든 사용자에 대한 품질 보장은 아니다.

전체 로컬 DB에는 기존 migration history drift 및 기존 `s65c_marketplace_metrics_v2` 실패가 있어 초기화하거나 결과를 숨기지 않았다. 신규 SQL은 별도 통과했고, 릴리스는 깨끗한 CI DB의 전체 검사 통과를 요구한다. 통합 시나리오의 화면 제목 선택자도 새 제목 계층에 맞췄으며 테스트 범위를 삭제하지 않았다.

## 출시 게이트 / 미확인

`release.yml`의 core + Chromium/WebKit 브라우저/전체 사이클 → quality 통과 후만 병합한다. 배포는 DB → Edge → 웹 순서이며 운영 `app-version`으로 머지 커밋을 확인한다.

통신사 실인증·실제 PG 청구·외부 알림 발송은 이번 로컬 회귀에서 대역을 사용했으므로 실제 외부 연동의 검증 근거가 아니다. 새 글꼴/비서 화면의 실기기 키보드·PWA/네이티브 설치 환경은 별도 사람 확인이 필요하다. 개인정보 고지의 법률 검토나 모든 AI 답변의 품질을 완료로 주장하지 않는다.
