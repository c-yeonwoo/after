## 2. 이 세션에 한 일 (PR 순서)

### PR #35 — 진단 P0 세 건 + 여성 경로

셋 다 성격이 같았다. **나중에 추가된 것이 초기 규칙을 상속하지 못한 자리.**

1. **비로그인이 티켓을 무한 발급할 수 있었다.** s19 가 `issue_ticket` 에 인자를
   붙이며 새 함수를 만들었는데(시그니처가 다르면 다른 함수다) `grant` 만 하고
   `revoke ... from public` 을 잊었다. PostgreSQL 은 함수 EXECUTE 를 PUBLIC 에
   기본 부여한다. anon 롤로 실제 발급을 재현했다(롤백).
2. **차단한 상대가 다시 소개되고 환불 안 되는 5,000원이 사라졌다.**
   `intro_exclusions` 를 확인하는 곳이 후보 조회 하나뿐이었다. 이제
   `exclude_pair` 가 기록하면서 큐까지 청소하고, `open_intro` 와
   `public_profiles` 가 각각 재확인한다. 차단이 열린 소개를 닫지 않던 것도
   함께 고쳤다 — 안 닫으면 불변식 2에 자리를 차지해 **끊은 쪽이 다음 소개를
   못 받았다.**
3. **약관이 약속한 파기를 코드가 안 했다.** `withdraw_account` 가 메시지·피드백·
   호감·사진 파일을 남겼다. 사진은 SQL 로 못 지워서(오브젝트는 남는다)
   클라이언트가 RPC **보다 먼저** 지운다. 순서가 곧 지워지느냐 마느냐다.

여성 경로도 같이 정리했다. `/me` 의 첫 숫자가 "0장 소개 / 0장 만남" 이었고,
**"여성은 무료" 라는 문장이 앱에 한 번도 없었다.** 그리고 거절 버튼이 없어서
유일한 거절 방법이 24시간 방치였다(그동안 상대의 30,000원도 묶인다).

### PR #36 — 프로필 뷰를 직접 조회하지 못하게

`public_profiles` 에 `grant select ... to authenticated` 가 있어서, 여성 세션의
`GET /rest/v1/public_profiles` **한 번**으로 권역 남성 전원이 나왔다(이름·직업·
사진 경로·인터뷰 답변). 사진도 전량 서명 URL 발급이 됐다.

뷰를 없애지 않고 **문만 좁혔다.** 컬럼 선택과 가시성 판정이 뷰 하나에 모여
있는 것은 이 스키마의 좋은 성질이고, 화면마다 복제하면 반드시 어긋난다.

작업 중 스스로 만든 함정 둘이 있었다. 둘 다 **조용한 실패**였고 pgTAP 이 잡았다.

- `select id::text from visible_profile_ids()` 의 `id` 가 함수 결과가 아니라
  바깥 `storage.objects.id` 로 **상관 참조**됐다. 에러 없이 사진이 5장에서
  0장이 됐다. 출력 컬럼에 이름을 주고 별칭으로 한정해 막았다.
- `returns public_profiles`(스칼라 복합형)는 볼 수 없는 사람을 물었을 때 0행이
  아니라 **전 컬럼 NULL 인 한 행**을 준다. `setof` 로 바꿨다.

### PR #37 — 프로필 문장 생성 + 카피·디자인

- **랜딩 1번 자리**를 위생요인("회사 이메일 인증")에서 환불 약속으로. 문구는
  일부러 좁게 썼다 — 환불은 24시간 무응답과 거절뿐이고, 조율하다 흐지부지된
  경우는 환불되지 않는다.
- **칩 두 벌 교체.** "잘 맞았던 사람" 이 덕목이라 정답이 있었고(모두가 같은 답을
  고르면 정보가 안 생긴다), 대화 주제에 "돈 쓰는 기준" 같은 초면에 못 누를
  항목이 있었다.
- **조사 버그.** 소개글에 `과(와)` 가 문자열 그대로 나왔다.
- **`compose-profile` Edge Function.** 모델이 한 줄 소개 3개와 소개글 1편을
  쓴다. **아직 안 켜져 있다**(§5-④).
- **분홍 면적 축소 + 색 있는 글자 걷어내기.** §3 참조.
- **홈에 소개 받기 스위치.** 남성이 로그인해서 소개가 없으면 할 수 있는 일이
  0개였다.

### PR #38 — 취향 문답

기다리는 화면에 할 일이 없는 문제와, **사용자가 채운 15개 항목 중 매칭에 쓰이는
것이 하나도 없는** 문제를 한 번에 풀었다. 양자택일 아홉 문항을 홈에서 세 개씩
받고, 큐레이션 화면에 일치 수와 문항별 대조표를 띄운다.

**모으는 쪽과 쓰는 쪽을 같은 작업에서 만들었다.** 모으기만 하면 홈의 "소개를
고를 때 이 답을 함께 봅니다" 가 거짓말이 되고, 그게 위 15개 항목이 이미 빠져
있는 함정이다.

### PR #39 — 비로그인 테이블 권한 회수

s31 배포 직후 확인 삼아 찔러 봤더니 **로컬 401 · 운영 200 `[]`** 이었다.
운영 프로젝트가 public 의 새 테이블을 Data API 롤에 **자동 노출**한다
(`auto_expose_new_tables` 구 동작). 로컬은 새 기본값이라 노출하지 않는다.

anon 에게 열려 있던 것: `ticket_orders` · `content_reports` · `intro_queue` ·
`admin_actions` · `preference_answers`. RLS 가 막아서 유출은 없었지만 방어선이
둘에서 하나로 줄어 있었다. 전부 회수하고 `alter default privileges` 로 앞으로
만들 것까지 막았다.

## 3. 색과 문체에 대해 정한 것 (코드에 안 남는 판단)

### `#B23A63` 은 값의 문제가 아니었다

사용자가 "`#DE6B87` 은 괜찮은데 `#B23A63` 이 촌스럽다" 고 했다. 대안을 찾아본
결과 **더 나은 값이 없었다.**

```
#DE6B87 을 종이 위 글자로 → 대비 2.82 (AA 4.5 미달)
통과할 때까지 어둡게      → 그게 정확히 #B23A63
틴트 제약을 없애고 최대   → #BA4666 (L 0.56), 사실상 동일
```

**종이 위에서 로즈로 읽히는 글자색은 물리적으로 없다.** 그래서 색 있는 글자를
쓰는 것 자체를 그만뒀다(28곳). 선택 상태는 틴트+색 글자에서 **채움+잉크 글자**로
바꿨다 — 그 패턴이 `#B23A63` 을 어둡게 묶어 둔 장본인이었다(`bg-primary/10`
위에서 4.5 를 지켜야 했다).

지금 `--primary-strong` 은 포커스 링과 차트에만 남는다. 회원 화면의 글자에는
쓰이지 않는다. 랜딩·로그인은 어두운 바탕이라 그대로 뒀다.

### 세라 카드가 AI 스러웠던 이유

원형 "S" 아바타와 "자동 안내" 알약 배지가 핵심이었다. **"여기 봇이 있습니다"를
그림으로 말하는 장치**인데, 우리는 그 말을 이미 글자로 하고 있었다. 중립 카드로
바꾸고 라벨 한 줄만 남겼다.

### fluent-korean 플러그인

`~/.claude/plugins/cache/fluent-korean` 에 설치돼 있으나 `outputStyle` 이
선택되지 않아 **적용 안 된 상태**다. 터미널 `claude` 의 config 메뉴에서 골라야
켜진다. 이 세션에서는 지침을 손으로 지켜서 썼다(엠대시 안 쓰기, 명사구 종결
안 하기). **이 지침은 코드 주석과 커밋 메시지에는 적용하지 않는다** — 지침
본문이 그렇게 정하고 있고 레포의 주석 문체가 이미 자리 잡혀 있다.

### 게임화를 넣지 않은 이유

취향 문답에 포인트도 연속 출석도 진행률 막대도 없다. 소개팅 서비스에서 점수판은
사람을 수집 대상으로 만들고, "고르는 피로 없이 한 사람에 집중" 과 반대 방향이다.
진행은 숫자로만 적는다(`0 / 9`) — 막대를 그리면 채우는 것이 목적이 된다.

## 4. 반복되는 함정 (다음 세션이 반드시 알아야 할 것)

1. **머지 ≠ 운영 반영.** DB 는 `npx supabase db push`, 프런트는
   `npm run deploy` 가 따로 필요하다. 순서는 **DB 먼저** — 반대로 하면 새 화면이
   없는 RPC 를 부른다. 마이그레이션이 있는 PR 은 두 명령의 간격이 곧 장애
   시간이라, **빌드를 미리 해 두고** 붙여서 돌린다(이번엔 22초).
2. **새 테이블을 만들면 운영에서 anon 으로 한 번 찔러 볼 것.** §2 PR #39.
   pgTAP `s32_anon_surface.sql` 이 표면을 0으로 고정하지만, 설정 차이는 로컬
   테스트로 못 잡는다.
3. **인자를 늘리면 새 함수가 생긴다.** `create or replace` 가 아니다. 구
   시그니처를 지우고, **`revoke ... from public` 을 다시 써야 한다.** s19 가 이걸
   잊어서 P0 이 됐고, s4 주석에 이미 경고가 적혀 있었다.
4. **반환 테이블의 컬럼을 늘리면 `create or replace` 가 거절된다.** drop 후 재생성
   (s31 이 `admin_like_pool` 에서 겪음).
5. **enum 값 추가는 별도 마이그레이션 파일**로. 추가한 트랜잭션 안에서는 쓸 수
   없다(s28 → s28b).
6. **`supabase config push` 금지.** `[auth]` 블록을 통째로 덮어써서 대시보드
   SMTP 설정이 날아간다.
7. **Auth → Email Templates 는 대시보드 관리라 배포에 안 실린다.**
   `supabase/templates/*.html` 을 고쳤으면 손으로 다시 붙여야 한다.
8. **`gh` 계정이 `nick603`(회사)로 튄다.** PR 만들기 전에
   `gh auth switch -u c-yeonwoo`.
9. **`zodOutputFormat` 은 zod 4 를 쓴다.** v3 스키마를 넘기면 죽는다. Edge
   Function 은 `npm:zod@4.5.4` 로 고정했고 앱은 zod 3 그대로다(모듈 그래프가
   달라 간섭하지 않는다).
10. **다루지 않는 값들.** service_role 키, `ANTHROPIC_API_KEY`, `TOSS_SECRET_KEY`,
    사용자 비밀번호. 명령만 드리고 사용자가 직접 넣는다.

## 5. 남은 일 — 전부 값이 필요하다

막는 순서대로.

### ① 알림 Vault 두 줄 (제일 위)

이게 없으면 **알림이 한 통도 안 나간다.** `drain_notification_outbox` 가
notice 만 남기고 건너뛴다. 대시보드 SQL Editor 에서:

```sql
select vault.create_secret('https://tsytwxtuczceyojkiaty.supabase.co/functions/v1', 'edge_function_base_url');
select vault.create_secret('여기에_service_role_키', 'service_role_key');
```

### ② 법정 고지 4건

`src/lib/policy.ts` 의 `BUSINESS`. 대표자 성명 · 사업장 주소 · 통신판매업
신고번호 · 개인정보 보호책임자 성명. 사업자명(널디선데이)과
사업자번호(538-04-03325)는 채워져 있다. **비운 채로 실사용자를 받으면
처리방침이 허위 기재가 된다.** 값이 null 이면 화면에 "법률 검토 전 초안입니다"
상자가 저절로 뜨고, 채우면 사라진다.

### ③ `ANTHROPIC_API_KEY`

```bash
npx supabase secrets set ANTHROPIC_API_KEY=sk-ant-...
```

넣으면 그 순간부터 문장 생성이 동작한다. **재배포 필요 없다.** 지금은 함수가
500 을 돌려주고 화면이 규칙 기반 초안을 쓴다(사용자에게 보이는 문제 없음).

키를 넣은 뒤의 **진짜 작업**은 첫 결과를 보고 `SYSTEM` 프롬프트의 금지 목록을
손보는 것이다. 문체 지침을 구체적으로 박아 뒀지만 검증은 못 했다.

### ④ Toss 가맹점 키

`TOSS_SECRET_KEY` 미발급. 베타(운영자 무료 발급, `app_settings.payments_enabled
= false`)를 끝내려면 필요하다.

Browser 도구의 `preview_start` 를 쓴다.

표본 계정 비밀번호는 전부 `eclipse-e2e-2026`. 계정별 상태는
`docs/e2e-sample-data.md` 에 있다. 요약하면 남성 m1~~m4 가 퍼널 단계별로,
여성 f1~~f5 가 상대 역할로, `admin@verify.local` 이 운영자다.

화면 확인 시 자주 쓴 조합:

- `m4` → 홈(소개 도착 + 스위치 + 취향 문답)
- `m3` → 홈(만남 진행 중이라 스위치·문답 없음)
- `f3` → `/requests`(거절 버튼)
- `f4` → 여성 `/me`(티켓 표면 없음) · 평가 큐
- `admin` → `/admin/curation?male=<m4 id>`(취향 대조표)

## 8. 사용자에 대해 알아 둘 것

- **인터뷰를 먼저 원한다.** 새 기능·버그는 코드보다 먼저 질문한다. 질문은 한 번에
  하나씩. 결정을 대신 하지 말고 2~3개 선택지를 트레이드오프와 함께 낸다.
  구현 계획을 보여주고 "진행" 전에는 코드를 쓰지 않는다.
- **근거 없는 수치·문구를 싫어한다.** "보통 2~3일 안에" 를 지운 것이 그 예다.
  약속을 넓히는 대신 지킬 수 있는 만큼만 쓴다.
- **커밋 메시지와 PR 본문을 실제로 읽는다.** 무엇을 왜 했는지, 특히 **왜 그 값이
  아니라 이 값인지**를 적으면 반응이 온다.
- **머지는 직접 한다.** PR 을 올리면 사용자가 머지하고 알려준다. 배포는 그 뒤에
  확인받고 실행한다.
