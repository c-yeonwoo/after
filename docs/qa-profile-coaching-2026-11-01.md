# 프로필 글 코칭 구현·QA — 2026-11-01

기존에 같은 조언이 반복된 원인은 `profileWritingCoaching`의 고정 문구·로컬 휴리스틱이었다. 해당 화면의 반복을 LLM 응답이나 API 장애로 해석하지 않는다.

## 구현

- 현재 공개 글의 작성 충실도를 내부 점수로 다시 계산하고 **85 이상이면 추가 과제를 제시하지 않는다**. 부족할 때만 빠진 이야기 소재를 안내하고, 충분하면 “궁금한 게 있으면 편하게 물어봐 주세요”로 끝낸다. 점수는 UI에 표시하지 않으며 매력, 소개 자격, 검증된 AI 품질 점수가 아니다. 부정 표현이나 명시한 경계를 결함으로 취급하지 않는다.
- `/profile-edit`, `/assistant-profile` 헤더의 매니저 버튼은 기존 대화를 공유하는 다이얼로그를 연다. 편집 폼을 유지하므로 닫아도 미저장 수정과 미전송 질문이 남는다. 저장된 프로필을 읽으며, 수정 중인 문장은 사용자가 대화에 붙여야 한다는 안내를 표시한다. 열기만으로 생성 요청을 보내지 않는다.
- 검증된 요청 필드 `purpose: "profile_coaching"`으로 “이 문장 어때?”, “수정했는데 어때?”도 본인 글 코칭에 연결한다. 서버가 현재 사용자 공개 원문을 읽고, 이번 메시지의 초안은 저장 완료로 표현하지 않는다. 동의·리비전·중복 요청·안전 경계는 유지한다.
- 실제 코칭은 수정할 곳이 있을 때 구체적인 원문과 예시를 제시하고, 충분한 글에는 억지 지적을 만들지 않도록 생성·검증 프롬프트를 함께 조정했다. 운영 플래그는 변경 없이 OFF이며 DB·마이그레이션 변경은 없다.
