# 로고 디자인 브리프 — 이클립스

외부 디자이너 전달용. 2026-08-09.

---

## 1. 서비스가 무엇인가

**강남·역삼권에서 일하는 직장인끼리, 한 번에 한 명씩 소개하는 1:1 소개 서비스.**

- 정식 명칭 **이클립스** (도메인 `eclps.kr`) / 화면에 쓰는 이름 **이클립스**
- 로고에 들어갈 워드마크는 **`after`** (소문자, 라틴)
- iOS 앱 · 대한민국 단독 운영

## 2. 다른 소개팅 앱과 무엇이 다른가

이 세 가지가 제품의 전부이고, 로고가 배반하면 안 되는 것들이다.

**① 회사 이메일로 재직을 확인한다.** 개인 메일(gmail·naver 등)은 가입이 막힌다.
"실제로 일하는 사람"이라는 최소한의 사실에서 시작한다.

**② 훑어보는 피드가 없다.** 좌우로 넘기며 고르는 화면이 아예 없다. 한 사람씩
순서대로 소개하고, 그 한 사람을 충분히 읽게 한다. *고르는 피로를 없애는 것*이
핵심 가치다.

**③ 사진과 스펙 대신 대화의 결.** 키·연봉을 비교하지 않는다. 요즘 시간을 어디에
쓰는지, 어떤 사람과 잘 맞는지, 무엇을 이야기하고 싶은지를 인터뷰 형식으로 보여준다.

그리고 **만남은 3만원 티켓**으로 신청한다. 상대가 24시간 안에 답하지 않으면 전액
환불된다.

## 3. 톤 — 여기가 가장 중요하다

**절제되고 성숙하고 진지하다. 그런데 낡지 않았다.**

문턱이 **일부러 높은** 서비스다. 재직을 검증하고, 한 명만 보여주고, 돈을 받는다.
그래서 밝고 친근하고 귀여운 방향은 제품을 배반한다. 반대로 무겁거나 고전적이면
20~30대 직장인에게 낡아 보인다.

클라이언트가 직접 말한 지향점:

> "매거진 같고 힙하고 영하지만 그래도 진지해 보이는 느낌"

## 4. 지금 워드마크 — 유지한다

**Archivo Black**, 소문자 `after`, 자간 `-0.035em`.

헤비 그로테스크의 단단함이 위 톤에 맞는다고 판단해 **바꾸지 않는다.** 세리프
계열(Instrument Serif·Newsreader 등)을 검토했으나 클라이언트가 현재 워드마크를
선택했다.

→ **디자인이 필요한 것은 워드마크가 아니라 그 옆에 놓일 마크(심볼)다.**

## 5. 필요한 산출물

| | 용도 | 조건 |
|---|---|---|
| **마크 (SVG)** | 헤더 · 앱 아이콘 · 파비콘 | `viewBox="0 0 32 32"` 정사각. 단색 |
| 앱 아이콘 1024×1024 | App Store 제출 | PNG, **알파 채널 없이** |

### 기술 조건 — 반드시 지켜야 하는 것

**① 단색이고 `currentColor` 를 쓴다.**
같은 SVG 파일이 두 배경에 얹힌다 — 코럴 배경의 앱 아이콘(흰 마크), 종이 배경의
헤더(코럴 마크). 색을 파일에 하드코딩하면 한쪽이 깨진다.

```svg
<!-- 이렇게 -->
<path d="…" fill="currentColor"/>
<!-- 이렇게 하지 말 것 -->
<path d="…" fill="#c72b10"/>
```

**② 16px 에서 형태가 남아야 한다.**
브라우저 탭 파비콘이 16px 다. 얇은 획(1px 이하로 내려가는 선), 반투명 겹침,
3개 이상의 요소는 그 크기에서 얼룩이 된다. **도형 1~2개, 굵은 획**이 안전하다.

**③ 헤더에서 24px 로 그려진다.** 워드마크 `after` 왼쪽에 `gap: 8px` 로 붙는다.

## 6. 색

| | 값 | 쓰임 |
|---|---|---|
| 코럴 | `#c72b10` | 브랜드 기본. 원래 노을색이라 골랐다 |
| 코럴(다크모드) | `oklch(0.755 0.145 40)` 계열 | 어두운 배경에서 밝게 보정 |
| 종이 | `#F5F2ED` | 라이트 배경 |
| 잉크 | `#17140F` | 라이트 텍스트 |
| 다크 배경 | `#14120F` | |

라이트·다크 양쪽에서 WCAG 대비를 통과해야 한다(자동 검사 스크립트가 CI 에 있다).

## 7. 피해야 할 것 — 검증된 실패들

### 데이팅 앱 클리셰

하트, 겹친 두 원, 사람 실루엣, 말풍선, 불꽃, 화살표. 전부 카테고리 변별이 안 된다.

### 이미 시도했고 접은 것

솔직하게 남긴다 — 같은 벽에 두 번 부딪히지 않도록.

| 시안 | 왜 접었나 |
|---|---|
| **해 + 지평선** (현재 마크) | 이름을 그림으로 그대로 설명하는 구조. **올드하게 읽힌다** — 스톡 아이콘 라이브러리에 수천 개 있는 모양이라 여행·웰니스 앱의 기본값처럼 보인다 |
| 해 + **윤슬**(물 위의 빛) | 위 문제를 강화하기만 했다. 24px 까지는 버텼지만 방향 자체가 틀렸다 |
| **누운 하트 반쪽** | 32px 이상에서만 겨우 읽혔다. 파비콘 크기를 감당 못 함 |
| **1:1** (네모 점 두 개) | 16px 에서 완벽히 살아남지만 차갑고 밋밋해 기억에 안 남는다 |
| **겹친 두 캡슐** | 세로 바 두 개가 **일시정지 아이콘(⏸)** 과 충돌 |
| **십자 교차** | 병원·약국으로 읽힌다 |
| **`//` 슬래시** | 개발자 주석 기호. 테크 냄새가 강하다 |
| **둥근 사각형 하나** | 형태가 비어 있어 앱 아이콘에서 색 블록으로 보인다 |
| **정수리에 V 갈라짐** | 어금니·왕관으로 읽힌다 |

**핵심 교훈**: 이름("이클립스")을 그림으로 설명하려 하면 올드해진다. 마크는
**추상**으로 가는 게 맞다.

## 8. 제품에서 뽑을 수 있는 개념 — 참고용

강제하지 않는다. 다만 이 서비스만의 사실들이라 클리셰를 피하는 데 쓸 수 있다.

- **한 번에 한 명** — 유일한 제품 규칙
- **오가는 길이 겹친다** — 매칭 조건이 "퇴근길이 겹치는 거리"다
- **읽는 것** — 훑지 않고 한 사람을 읽는다
- **해가 진 뒤** — 퇴근 후라는 시간대 (단, §7 참고: 직역은 실패했다)

## 9. 확인할 것

- 16 / 20 / 24 / 32 / 48 / 72px 로 나란히 렌더해 볼 것 (작은 크기가 진짜 시험)
- 코럴 타일 위 흰 마크 · 종이 배경 위 코럴 마크 양쪽
- 다크모드 배경(`#14120F`)
- 워드마크 `after`(Archivo Black) 옆에 24px 로 붙였을 때의 균형
