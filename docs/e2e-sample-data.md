# E2E 표본 데이터

```bash
npm run e2e:seed          # = bun scripts/e2e-seed.mjs
```

**로컬 Supabase 전용**이다(`127.0.0.1:55321`). 멱등하다 — 몇 번 돌려도 같은 상태가
된다. 진행 상태(소개·만남·티켓·신고·주문)를 매번 걷어내고 다시 세우므로, 테스트로
흐트러지면 그냥 다시 돌리면 된다.

## 비밀번호

전 계정 공통 **`eclipse-e2e-2026`**. 로컬 전용 값이고 운영 계정에는 쓰지 않는다.

## 계정과 단계

| 계정                 | 이름      | 지금 상태                     | 여기서 볼 것                    |
| -------------------- | --------- | ----------------------------- | ------------------------------- |
| `m1@verify.local`    | 연우 (남) | 만남 확정 · 대화 열림         | 대화, 만남 후 피드백, 신고·차단 |
| `m2@verify.local`    | 민수 (남) | 소개 도착 (티켓 사용 전)      | 프로필 읽기 → 만남 티켓 쓰기    |
| `m3@verify.local`    | 지호 (남) | 티켓 씀 · 상대 응답 대기      | 24시간 환불 카운트다운          |
| `m4@verify.local`    | 태오 (남) | 소개 없음 · 큐에 후보 1명     | **소개 열기부터 끝까지**        |
| `f1@verify.local`    | 서연 (여) | 연우와 확정됨                 | 여성 쪽 확정 화면 · 대화        |
| `f2@verify.local`    | 지우 (여) | 민수에게 호감 줬음            | 민수 소개 카드의 상대           |
| `f3@verify.local`    | 하람 (여) | 지호의 만남 선호 답할 차례    | 날짜·역 고르기                  |
| `f4@verify.local`    | 나윤 (여) | 평가할 후보 여러 명           | 호감/패스 평가 큐               |
| `f5@verify.local`    | 예린 (여) | 사진 검수 대기                | 운영자 승인/반려가 반영되는지   |
| `admin@verify.local` | 운영자    | 신고 1 · 주문 1 · 사진 1 대기 | `/admin` 전체                   |

전원 강남·역삼권, 가입 완료(`onboarding_step = 7`), 사진 승인됨(f5 제외).

## 어디서 보는가

앱 번들과 dev 서버가 **둘 다 로컬을 봐야** 이 데이터가 보인다.

```bash
npm run dev                                  # 웹  → localhost:55317
npm run build:app:dev && npx cap sync ios    # 앱  → 시뮬레이터
```

> ⚠️ `npm run build:app` 은 **production 모드**라 운영 DB 를 본다. 시뮬레이터에서
> 표본이 안 보이면 이걸로 빌드했는지 먼저 의심한다.

## 추천 순서

1. **m4 태오** — 소개 열기 → 프로필 읽기 → 만남 티켓 → 선호 대기까지. 가장 긴 길.
   (상대 나윤의 선호 응답은 `f4` 로 갈아타서 넣는다)
2. **f3 하람** — 지호의 요청에 날짜·역을 답한다. 그 다음 `m3` 으로 갈아타면
   날짜 확정 화면이 열려 있다.
3. **m1 연우** — 이미 확정된 건이라 대화·피드백·신고·차단을 바로 볼 수 있다.
4. **f4 나윤** — 평가 큐(호감/패스). 호감을 주면 그 남성의 큐 후보가 된다.
5. **admin** — 큐레이션(후보 세우기) · 사진 검수 · 신고 처리 · 주문 발급.

## 가입 자체를 시험하려면

새 메일로 가입하면 된다. 인증 코드는 **개발 환경에서 자동으로 채워진다**
(`devFetchLatestOtp`) — 메일함을 볼 필요가 없다. 다 쓰고 나서 표본을 다시 돌리면
미완료 계정(`onboarding_step < 7`)은 자동으로 정리된다.

## screenshot-seed 와의 차이

`scripts/screenshot-seed.mjs` 는 **한 계정을 가장 보기 좋은 한 지점**에 놓는다
(스토어 스크린샷용). 이 스크립트는 반대로 **여러 계정을 서로 다른 단계**에 흩어
놓아서, 어느 화면을 테스트하든 그 앞 단계를 손으로 만들지 않아도 되게 한다.
둘을 번갈아 돌리면 서로의 상태를 덮으므로, 스크린샷을 다시 뽑을 때는
`screenshot-seed` 를 마지막에 돌린다.
