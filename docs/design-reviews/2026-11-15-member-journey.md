# 애프터 회원 화면: 위에서 아래로 무엇을 읽는가
2026-11-15 · 홈 → 소개 → 만남 → 후기. 결론은 색을 바꾸는 것보다 **결정에 필요한 정보를 결정 버튼 앞에 두는 것**이다. 소개 상세의 주인공은 회원이고, 매니저는 그 사람을 읽는 데 도움을 준다.

| 화면 | 읽는 순서와 판단 | 이번 조치 또는 후속 검증 |
|---|---|---|
| 가입·프로필 수정 | 가입은 계정 확인, 수정은 이미 작성한 정보로 복귀하는 작업이다. 같은 긴 폼처럼 보이지 않도록 단계와 저장 행동이 각자 있어야 한다. | 현재 분리된 라우트·사진/기본정보/생활/소개글 그룹 유지. 긴 소개글을 수정한 다음 저장으로 돌아가는 시간은 실사용 관찰 대상. |
| 홈·여성 | 상대가 누구인지 → 왜 나에게 소개했는지 → 더 볼지. 기존에는 소개 이유가 열기 버튼 뒤에 남았다. | 사진·한 줄과 이유를 먼저 읽고 카드 끝에서 프로필을 연다. |
| 홈·남성 / 열기 전 | 이유 → 열람 조건 → 열기. 아직 공개할 수 없는 얼굴이나 이름이 없어도 결정을 내릴 근거가 필요하다. | 홈의 설명 우선 순서 유지. 열람 전 상세에서 소개 이유 위 구분선과 중복 간격을 없앴다. |
| 소개 상세 | 이름·한 줄 → 사진 → 매니저의 해석 → 공개 정보·인터뷰. 이전에는 운영 안내와 매니저의 일반적인 읽기 안내가 사람보다 앞에 섰다. | 자기소개와 이름을 한 묶음으로, 매니저 이유는 사진 다음에 한 번 배치. 요청이 실제 진행 중이면 상태 안내 유지. 선택·신고는 기존 위치. |
| 만남 목록·날짜 선택·상대 대화 | 대상과 상태 → 가능한 날짜·장소 → 확인·대화. 시간 및 상대의 응답을 기다리는지 여부가 안내문보다 중요하다. | 기존 분기 유지. 목록 첫 설명과 날짜 선택 화면 안내는 실제 약속 데이터가 보이기까지 얼마나 밀리는지 작은 기기에서 후속 관찰. |
| 만남 후기 | 이번 만남 평가 → 추가 기록 → 다음 소개 선호 → 보내기. 평가와 선호는 목적도 공개 범위도 다르다. | 비공개 안내를 한 문장으로, 후기 메모는 3줄부터, 다음 선호는 별도 그룹으로. 노쇼에는 다음 소개 선호를 묻지 않는다. |
| 내 정보·알림·설정 | 내 정보는 수정 진입, 알림은 시간순 확인, 설정은 항목 탐색이 목적이다. 소개용 카드 표현을 그대로 복사할 이유가 없다. | 목록 구조 유지. 설정의 반복 구분선·넓은 섹션 간격은 소개 받기 설정을 찾는 시간으로 다음 개선을 판단할 것. |
| 상점·티켓 | 무료/유료 상태 → 제공 내용·사용 조건 → 신청/결제. 유료 행동의 비용·효과는 누르기 전까지 보여야 한다. | 소개 화면 단순화를 결제 고지나 확인 절차에는 적용하지 않았다. |
| 운영 큐 | 추천 순서 검토 → 자동 채우기 또는 수동 조정 → 저장. 목록의 순서와 자동 채우기가 다르면 운영자가 순위의 뜻을 잘못 읽는다. | 목록과 자동 채우기가 같은 서버 순서를 사용한다. 저장 전까지 배달하지 않는다. |

**검토 방법.** Impeccable layout의 읽기 순서·근접성, Damir Sokolovsky의 [Unslop](https://github.com/heydamir/unslop)의 정보 밀도·간격 원칙을 참고했다. 브랜드 팔레트와 글꼴은 유지했다. 홈·열람 전후·후기는 합성 회원을 사용해 브라우저에서 확인했고, 나머지는 라우트와 컴포넌트 구조를 읽은 검토다. 전체 앱 실기기 사용성 시험으로 해석하지 않는다.

**운영 관찰.** 후기 선호는 배제 기준이 아니다. 실제 회원이 쌓이면 선호 불일치 회원의 대기시간, 추천 초안에서 운영자가 바꾼 순서와 변경 사유, 후기 선호 선택률을 함께 보자. 후보가 적거나 너무 오래 기다릴 때까지 순위 보정이 노출을 왜곡하지 않는지 확인하기 위한 지표다.
