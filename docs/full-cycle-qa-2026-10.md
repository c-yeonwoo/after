# 애프터 한 사이클 QA · 2026-10

## 범위와 증거 구분

로컬 Supabase와 모바일 폭 Chromium으로 남성 2명·여성 4명의 가입, 사진 업로드, 프로필 작성, 사진 검수, 호감/거절, 수기 큐, 티켓 주문, 약속, 알림 원장, 취소/복구, 후기와 운영자 개입을 검증했다. 회사 이메일·SMS 전달·PG 공급자는 명시적 테스트 대역이다. 실제 운영 회원과 섞거나 실 결제·문자를 발생시키지 않는다.

시간 경과는 **해당 테스트가 만든 만남과 티켓만** 조정하고 실제 DB의 만료/알림 함수를 실행한다. 서버 시계 전체, 다른 회원의 약속은 변경하지 않는다. 인앱 알림 생성, 공급자 접수, 기기 수신을 같은 성공으로 취급하지 않는다.

## 추가 경험 점검

C11: 약속 전 대화방에 후기 링크가 노출되고, 이미 제출한 후기의 재방문도 새 작성으로 보여 혼란을 줄 수 있다. 약속 이후에만 링크를 보이고 서버 자격/기존 제출을 확인해 분기한다.

C12: 인앱 알림 원장 생성이나 APNs의 접수는 외부 전달/실제 읽음을 보장하지 않는다. 웹 베타는 브라우저를 닫으면 현재 별도 외부 알림이 없다. **양측 인앱 안내의 읽음 표시가 없으면 자동취소·경고를 보류하고 운영 연락 대상으로 표시**한다. 한 명만 참석을 확인한 약속도 취소하지 않는다. 읽음 표시는 알림 목록 방문에 따른 앱 기록이며, 문장을 실제로 읽었다는 증명은 아니다. 카카오는 별도 승인·연동 후 검증한다.

C13: 후기의 보내기 버튼이 비활성→활성으로 바뀌는 색상 보간 중 대비가 3.21:1까지 떨어진다. pressable의 배경·글자 색상 애니메이션을 제거하고 눌림 transform/opacity는 유지한다. reduced-motion에서는 transition을 없앤다.
